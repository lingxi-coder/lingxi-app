# 统一聊天收件箱

本功能覆盖 Desktop、Android、iOS、Web 的助手、好友、团队及已有服务会话。好友 pair 与团队入口使用同一个 `team:sourceId:conversationId`，本地助手与远控使用同一个稳定来源标识。项目、团队与执行设备仍是会话的原始上下文。

2026-11-18 的候选实现已合入 main 的 `12ec044a7` 聊天 UI 优化，保留统一顶栏、输入框及消息布局。代码在隔离分支 `codex/unified-inbox-20261117`；原主工作区的其他修改未纳入。

产品清单和锁文件固定 Harness 提交 `3250195b9a9b77845af78a6a997fbf78564dd969`，位于独立候选分支 `codex/unified-inbox-runtime-20261117`。实际远端依赖解析通过，桌面依赖图中的 84 个 Harness 包均来自该 SHA，没有提交本地路径补丁。

## 界面与隐私

- 聊天页提供全部、未读、待处理及类型筛选，支持标题开头搜索、置顶顺序、静音、归档和批量已读。虚拟列表保留键盘焦点和当前会话标识。
- 阅读水位、手动未读提醒、待批准／待输入、失败、提及分别保存。阅读不会批准工具或解决待处理事项，归档不会被新消息取消。
- 助手摘要同步默认关闭，需账号明确开启，可对单个本地会话关闭。关闭后撤销云端摘要及其通知访问。正文保留在原宿主，摘要授权不授予远控正文权限。
- 云端助手标题只使用宿主确认来自用户重命名的标题；无法确认来源的旧标题使用通用名称。云端预览使用状态文案。
- 私聊已读回执默认关闭，双方启用才展示对方水位。自己的跨设备阅读同步不受此开关影响。群聊不公开逐人已读矩阵。

## 阅读与版本契约

`packages/inbox/contracts.ts` 定义跨 JavaScript 客户端的接口；原生模型映射同一 HTTP 协议。

| 字段 | 职责 |
| --- | --- |
| `ref.kind/sourceId/conversationId/generation` | 来源身份与授权代次 |
| `sourceCursor/sourceRevision` | 来源消息／语义结果水位与来源状态版本 |
| `readThrough` | 累计阅读水位，只前进 |
| `manualUnread/manualUnreadRevision` | 独立手动提醒及 CAS 版本 |
| `preferencesRevision` | 置顶、静音、归档的 CAS 版本 |
| `pendingActionAt/pendingActionRevision` | 当前待处理事项的时钟与身份 |
| `failureAt/failureRevision` | 无正文结果也存在的终态失败时钟与身份 |

前台、当前会话的已提交内容实际可见 300ms 后，按连续阅读位置推进，每秒合并一次，离开时补交。列表、预加载、后台和通知预览不推进。发送自己的消息也不代替阅读。通知使用独立的、重新鉴权的精确消息或任务预览；明确返回会话后才恢复普通阅读。

`markRead` 携带来源水位及观察到的手动版本。待处理及状态失败的通知取消还需要匹配的 `observedPendingActionRevision`／`observedFailureRevision`；另一设备的较大水位不能替请求扩展其观察范围。手动未读不回退真实水位。迟到的个人设置通过独立版本拒绝，不能重放覆盖另一设备的新设置。

全局全部已读通过 `markAllReadSnapshot` 在服务端建立固定 Firestore `readTime`，后台每页 50 条处理，逐条重新检查授权代次。新消息、新手动提醒和待处理状态保留。任务可通过 `readBatchStatus` 恢复；新请求只在在线时创建，离线重启只恢复已有任务，不在重连时悄悄建立新边界。快照过期后需用户重新发起。

## 助手来源活动

Harness `crates/session/src/jsonl/activity.rs` 使用成功落盘的外层消息 UUID、语义回复身份和独立处理检查点维护活动。一次回复的多个文本块计为一个语义结果。工具日志、token 更新、编辑、重放与压缩不会产生新的未读序号。

来源数据位于宿主的 `inbox-activity` 目录。初次初始化冻结基线 B，历史不制造未读，后续结果正常计数。处理意图可在崩溃后恢复，来源身份与读取游标不依赖消息总数、文件时间或原始消息索引差值。

`session.activity` 返回最多 50 个语义位置。`session.activityPreview` 与原生本地 `assistantActivityPreview` 精确解析一个结果，不遍历远端历史；只返回已提交的助手文本，最多 16 个文本块、32,768 个 UTF-16 单元。找不到、已压缩或超过界限时明确返回不可用，不自动确认任何消息。远端请求在异步 I/O 前后校验当前 attachment 及共享权限。

## 云端投影与存储

来源消息、原有 Teams `reads.lastReadSeq` 继续作为权威。新 HTTP 写入在原事务中更新阅读与投影，旧 SDK 写入通过有序事件补齐。投影写入不覆盖个人设置。

- 每用户每会话一条摘要，预览文本不建立索引。账号监听数量固定为摘要变更查询与 16 分片角标查询，随会话数量增长不增加逐会话 reads 监听。
- 每个来源会话的 `inboxCountEvents` 保存一份无正文的规范计数索引。不存在每收件人每消息的未读文档。普通新消息增量更新；部分阅读、恢复、撤回才进行每类最多 100 条的校准查询。
- 共享计数索引随来源消息数增长；每用户摘要、授权与阅读检查点随会话数增长。200 人群的摘要写时扇出仍随收件人数增长。
- 会话与消息每页 50 条，活动消息窗口最多 200 条。窗口移出不当作删除，编辑与撤回通过有界变更流按 ID 更新。
- 可淘汰 SDK 缓存配置了 LRU；移动端预算 32MiB，桌面总预算目标 128MiB。正文、草稿、阅读确认和已接受操作不进入自动淘汰范围。云端缓存使用有限授权租期，重连或明确撤权后重新鉴权及清理。
- 新增同步队列限制 16MiB／10,000 项，合并兼容操作，满时明确报错。手动提醒及个人设置保留版本，不能为合并丢失因果关系。
- 通知历史保留 30 天且至多 1,000 项；投递去重 7 天；删除标记 30 天；来源处理检查点长期保存。TTL 到期物理删除是异步的，读取仍检查逻辑有效期。

## 通知与灰度

私聊、提及及回复优先；普通群消息累计未读，默认不弹通知。待输入／批准保留 6 秒窗口，后台结果合并 5 秒，终态失败使用独立失败身份去重。

当前会话使用页内状态，前台其他会话使用应用内横幅，后台使用系统通知。每个事件固定活跃设备选择，其他设备等待 15 秒。成功投递到第一台设备不取消其他设备，仅实际已读覆盖事件才取消兜底。每次投递重查权限、代次、静音、待处理状态与有效期，以事件 × 设备去重。关闭通知不推进已读。

`INBOX_NOTIFY_ROLLOUT_PERCENT` 控制新通知策略的账号比例（0–100，默认 100）。`INBOX_NOTIFY_ALLOW_SHA256` 是逗号分隔的账号 UID SHA-256 白名单；只配置白名单时比例默认 0。灰度外保留既有 Teams 推送路径。摘要同步仍由每账号、每会话明确授权控制。

部署前检查：

1. 发布 `(default)` 数据库规则及收件箱复合索引，等待索引可用，再发布函数及 Hosting 路由。
2. 配置 Cloud Tasks API、任务队列、服务账号调用权限及 Eventarc 触发权限；沿用已有推送服务账号，不把任务执行端点公开给客户端。
3. 为 `expiresAt` 字段启用相应 collection group TTL；保留长期水位检查点。确认历史快照读可用及任务延迟未越过快照窗口。
4. 先设通知比例 0，加测试账号白名单后验证真实推送、退出账号、撤权、恢复和延迟投递，再逐步提高比例。
5. 回滚客户端入口或通知比例时保留来源阅读、手动提醒、个人设置及已接受任务。不能把回滚当作重置计数或删除正文。

本地 Chromium 以 10,000 个合成会话及模拟 100ms RTT，20 次缓存导航最终测得 p95 53ms；这不是手机首屏或生产同步指标。250px 侧栏及 320px 视口、200% 字号下验证了行、来源和三个 `99+` 计数不重叠。200 成员的单消息 Firestore 模拟器最终样本测得投影 p95 230ms，排除 Cloud Tasks 排队及真实网络。

该 200 人样本记录：共享规范事件写入 1 次、摘要写入 200 次、摘要信号写入 200 次、角标写入 199 次、逻辑来源读取 806 次、校准查询 0 次。`inbox.fanout` 结构化日志持续记录这些逻辑量与耗时；Firestore 多范围索引扫描还可能产生索引条目读取费用，需要生产账单核对。

仍需运行真实跨设备配对、签名安装、前后台通知点击、系统免打扰、大字体、屏幕阅读器、多语言及长期断网／存储增长验收。设计目标仍为：缓存首屏桌面 p95 ≤200ms、手机 ≤300ms；100ms RTT 下会话状态与角标 p95 ≤2 秒。未经实际测量不得将这些目标记作通过。
