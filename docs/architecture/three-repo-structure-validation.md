# Three-repository structure migration — validation record

LingXi keeps product entrypoints and clients in its root workspace. Harness owns Agent, session, permission, tools, and platform composition. Mobile Linux SDK owns neutral execution interfaces, rootfs lifecycle, PTY, Android/iOS guest backends, and native support. Android/iOS host adapters retain native app capabilities while delegating Linux execution to the SDK.

Pinned sources:
- Mobile Linux SDK: `acdf47a4c01ce1c3ccab4e8aa3f8e51fcffac771` (draft PR #3).
- Harness: `5d2aa7178624c9b277c6173ea1f98386e706129c` (draft PR #3).
- llm-client: `9b0323f10f76c5834acafedaa04470c4e96346f2`.

Validation evidence:
- SDK: CI and real x86 guest runs passed at `acdf47a`; 56 Python tests, including stale iSH cache and missing-symbol negatives, passed. A rebuilt iOS native-support artifact passed Swift import, digest and policy-symbol checks; the prior unpatched artifact failed the new symbol gate.
- Harness: 21 CI jobs passed at `5d2aa7`, including Linux seccomp, Android/iOS compile and feature checks. Six job categories retain the same failures as the pre-structure migration commit: full lint, unit tests, parity fixtures, supply chain advisories, brand/skill gates, and Windows desktop.
- LingXi: 76 Harness and 7 SDK packages have one full-SHA source each. Root Cargo workspace/all-target check passed at the final pins with three pre-existing missing-docs warnings in test fixtures; `cargo fmt --all -- --check` passed. Final-pin Android direct/play native support, Kotlin/Gradle unit tests and APK helper checks passed. Both ABI variants of the direct and play FFI libraries and APKs were rebuilt from product commit `6f37107d096a9abc7c0024a11a035eb417edddfb`; the generated Kotlin bindings matched byte for byte. `com.lingxi.code.direct.debug` installed and started on the SM-S9310 (Android 36), and `com.lingxi.code.debug` installed and started on the connected 24117RK2CC (Android 36). The play variant also installed and started on an isolated Android 37 emulator with 16 KiB pages before this final product rebuild. A shared native-support staging directory now feeds both variants; helper bytes matched across staging directories and Maven, and both APK helper checks passed after building both variants. The standalone clean-SDK sample consumed the final-pin full AAR and passed ten real-rootfs checks on the SM-S9310 and the emulator with R8 minification. LingXi's Maven staging was then restored to native-support-only and reverified. The earlier pin also executed PRoot/mksh on the phone and PRoot/Toybox on an emulator. Device instrumentation compilation is blocked by stale voice adapter references in three pre-structure test files; these errors were present in the preparation baseline.
- iOS: final-pin native support and rootfs supply chain checks passed. The final XCFramework's device arm64 and simulator arm64/x86_64 Rust static libraries all built from product commit `6f37107d096a9abc7c0024a11a035eb417edddfb`; all three archives contain that commit identifier. The FullDebug app linked and signed with the native policy hooks, and `com.lingxi.code.full` installed and launched on the unlocked iPhone 11 without changing the Store app. The selected offline Local Apps guest test did not run: Xcode twice failed its incremental app installation before starting XCTest because its device manifest reported version `0` instead of `8721 2.4.1`. A normal `devicectl` overwrite installation succeeded but did not fix Xcode's incremental install; uninstalling the test app was avoided because its data container could not be fully backed up through a workspace symlink. Thus LingXi's physical-device guest behavior remains unverified. The final-pin simulator ran 207 focused tests: 205 passed and the same two assertions failed as on the pre-split source.
- Standalone iOS SDK device test: release FFI and native support were built and verified from clean SDK revision `acdf47a4c01ce1c3ccab4e8aa3f8e51fcffac771`. The signed sample app installed and launched on the iPhone 11. With toolchain rootfs ZIP SHA-256 `10b954ab95fc92a3e0e7b2fd5327fd93216aa124b18e5166749a489fa3bc128c`, cold boot did not leave `install-boot` before the 600-second limit. The device then contained a staging tree with 582 entries, while the supplied ZIP has 15,384 entries (including 8,187 `__MACOSX/` entries). A previously installed sample completed the guest contract on the same device, but its source revision was not established as the final pin and is not counted as final acceptance. The final SDK rootfs install and guest execution remain open.
