# Three-repository structure migration — validation record

## Android PRoot-only candidate (2026-09-28)

Android no longer links the Minijail, mksh, toybox, or JNI PTY host-shell packages. The Agent Shell and terminal use the same PRoot SDK runtime; the Agent requires a canonical workspace mount before exposing guest file tools. The old stateless Android Mobile Linux FFI calls and Kotlin compatibility wrapper were removed, and the Kotlin bindings were regenerated from the new `android-aar` library.

The Android code pin is SDK `224f1fb1fd0f24b5e138c9095e22a6c20b375eb1` in both Harness and LingXi; LingXi pins Harness `5940a5156cc8ed39432601ac37694509817b705c`. SDK PR #4 later added only a test-inventory correction at `fa85819aba0258ab9f2eeaa433eb705c7134e7bd`; all of its CI checks passed, including both Android builds and the independent real-x86 job. It merged into SDK main at `eeab57459c5a4e78e5f20b321c70c7ad550309d8`, preserving the pinned code commit in history. Harness PR #4 passed its Android jobs, but the inherited structure branch still has failing brand, lint, parity, supply-chain, and Windows desktop checks. Harness PR #4 remains unmerged.

Focused LingXi evidence: `android-aar` host tests (9), direct Kotlin compilation, selected direct JVM suites, 20 host SDK integration tests, 11 source-identity tests, generated translation checks, Cargo formatting and all six product repository gates passed. ARM64 and x86_64 direct JNI libraries were rebuilt, and the native-support AAR contains exactly PRoot, loader, and policy launcher for each ABI, with no second Rust core. The previously missing 58 x86_64 APK closure files were fetched from the SDK's fixed URLs and each SHA-256 matched its locked pin; the 58 ARM64 files and both rootfs archives were also reverified. The formal release staging checked 70 licensed packages and 6,093/6,094 immutable rootfs entries. Android's asset merger expands a `.gz` asset and drops that suffix, so the app now packages the original gzip bytes as `rootfs.tar.gz.bin` and presents the manifest's `rootfs.tar.gz` filename to the SDK installer. The strengthened final APK gate verified every staged asset byte and native helper in `app-direct-debug.apk` (SHA-256 `89eedcd22c3773060b7da1c4390c96c6262726bd8576b3eb351fe9921067b1b1`); no old shell helper or second Rust runtime is present. `adb devices -l` found no connected device, so installation, guest execution, and Agent Shell behavior on hardware remain unverified.

The SDK source checkouts and product user-data directories were not modified. The final APK gate has positive fixture coverage and negative checks for absent rootfs assets and reintroduced mksh. LingXi's local main was fast-forwarded to the PRoot-only integration; this repository has no Git remote. Product device execution and the blocked Harness PR checks remain open.

LingXi keeps product entrypoints and clients in its root workspace. Harness owns Agent, session, permission, tools, and platform composition. Mobile Linux SDK owns neutral execution interfaces, rootfs lifecycle, PTY, Android/iOS guest backends, and native support. Android/iOS host adapters retain native app capabilities while delegating Linux execution to the SDK.
