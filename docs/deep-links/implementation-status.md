# Deeplink implementation and acceptance

## Implemented

The canonical contract supports `lingxi://…` and `https://lingxios.net/open/…` across Desktop, iOS, Android, Web and CLI. TypeScript, Rust, Swift and Kotlin consume a shared corpus of 24 valid and 29 invalid links. Resource identifiers preserve case; persisted message UUID parameters normalize to lowercase.

- Session and message links resolve existing local data. Persisted JSONL UUIDs pass through the pinned Harness SDK, bridge and UniFFI DTOs. Optimistic user rows use explicit turn tokens; assistant/tool rows retain authoritative UUID aliases, including grouped tools. Missing resources and ambiguous project/configuration scope are errors.
- New-conversation links prefill an editable draft without submission. Existing drafts, import previews and terminal editors defer navigation. Terminal command payloads require explicit edited-command confirmation.
- Desktop and native clients route their existing settings, provider, MCP/skill/plugin, scheduled task, terminal, local-app and runtime/detail surfaces. A destination unavailable on that platform reports an error. MCP names resolve the requested scope; unscoped duplicates require disambiguation.
- MCP, skill, plugin and provider imports preview a proposal before the existing administrative API applies it. Links reject credential fields; credentials must be entered locally. No link sends a prompt, installs a plugin or executes a command merely by parsing/opening.
- Desktop queues cold/warm OS deliveries until restoration and renderer readiness, replays unacknowledged deliveries after recreation, and deduplicates only pending requests. An explicit unknown workspace cannot fall back to the current project.
- CLI `link` generates canonical links. `open` hands off to Desktop; `open --cli` resolves local session/message/project/new destinations, restores a safe composer draft, and supports an anchored fullscreen transcript. Noninteractive and conflicting submission/resume options are rejected. A custom local store cannot silently hand a resource to an unverified Desktop store.
- Web landing pages offer explicit Open, Copy and Download actions without automatic redirection. Windows/Linux protocol registration/removal helpers and macOS URL-scheme packaging are included.

Message links address the main session transcript. Child-agent navigation uses `runtime/agent/<id>`; a child UUID must not be advertised as a message in its parent transcript. No cloud sharing, remote connection or automatic post-install restoration is implied.
