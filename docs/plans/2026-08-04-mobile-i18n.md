# Mobile i18n (iOS + Android) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add multi-language support (zh-Hans base / zh-Hant / en / ja / ko) to the iOS (`apps/ios/native`, SwiftUI) and Android (`apps/android/native`, Compose) clients: full UI + permission strings + app name, with follow-system + in-app override.

**Architecture:** Single canonical translation source (`resources/translations/*.json`, snake_case keys) + a generator (`generate.py`) that emits iOS String Catalog (`Localizable.xcstrings`) and Android `strings.xml` locale variants. iOS switches language via a `LocalizationManager` (UserDefaults + `Bundle.main` swizzle + root-view refresh); Android via `AppLanguageStore` (SharedPreferences) + `attachBaseContext` locale wrap + `recreate()`. Both rewire the existing (currently inert) language pages.

**Tech Stack:** Python 3 (generator), XcodeGen `project.yml` + String Catalog (.xcstrings), SwiftUI `String(localized:)`, Android Jetpack Compose `stringResource()` / `R.string`, Kotlin.

**Spec:** `docs/superpowers/specs/2026-08-04-mobile-i18n-design.md`

## Conventions (apply to ALL extraction tasks)

**Key naming:** flat snake_case, feature prefix: `chat_`, `composer_`, `settings_`, `local_apps_`, `permission_`, `cron_`, `terminal_`, `voice_`, `drawer_`, `onboarding_`, `common_`, `app_`. Example: `composer_placeholder`, `settings_language_title`, `common_cancel`.

**Canonical JSON format** (`resources/translations/<locale>.json`):
```json
{
  "app_name": "灵犀",
  "common_cancel": "取消",
  "settings_language_title": "语言",
  "__info_plist__": {
    "CFBundleDisplayName": "灵犀",
    "NSCameraUsageDescription": "灵犀使用相机拍摄照片供模型分析。"
  }
}
```
- `__info_plist__` is iOS-only; generator maps it into the catalog's InfoPlist keys.
- Android `app_name` from top-level `app_name`.
- Locale keys are canonical: `zh-Hans` (base), `zh-Hant`, `en`, `ja`, `ko`.

**Persisted app-language codes** (existing convention, keep): `""` = follow system, `zh-CN`, `zh-TW`, `en-US`, `ja-JP`, `ko-KR`. Map to canonical for resources: zh-CN→zh-Hans, zh-TW→zh-Hant, en-US→en, ja-JP→ja, ko-KR→ko.

**Non-translatable:** Android test tags (`UiTags.kt`), log messages, exception strings, internal identifiers → mark `translatable="false"` or skip. iOS: never create keys for logs/internal strings.

**iOS replacement rules:**
- `Text("字面量")` → `Text("snake_key")` (key = catalog key; zh-Hans catalog value renders)
- `"字面量"` passed to SwiftUI label params (`label:`, `value:`, `sub:`, `title:`, `footer:`, accessibility labels) → `String(localized: "snake_key")`
- Interpolation: `"共 \(n) 个"` → `String(localized: "settings_providers_enabled \(n)")` — key must be the FULL literal with `\(n)`; catalog value `"共 %lld 个"` (`%lld` for Int). Catalog value uses `%lld`; Swift `String(localized:)` interpolated args auto-format.
- Do NOT touch: `Info.plist` literal values (catalog overrides at build), voice-language codes, model/provider names.

**Android replacement rules:**
- Composable: `Text("字面量")` → `Text(stringResource(R.string.snake_key))`; same for `contentDescription`, `semantics`, `sub =`, `label =`, `footer =`, button text.
- `stringResource(R.string.key, arg)` for `%1$s`-style placeholders (use positional `%1$d`/`%1$s` in resources).
- Non-composable (ViewModel/notification): `context.getString(R.string.key)`; ChatViewModel → convert to `AndroidViewModel` if not already, or inject `ResourceProvider` (decide per file at implementation; prefer `AndroidViewModel`).
- `translatable="false"` for internal strings (test tags, log formats, URIs).

**After EVERY extraction batch:**
1. Update `resources/translations/zh-Hans.json` with new keys (value = original Chinese literal).
2. Run `python3 resources/translations/generate.py` — must exit 0 and print `OK: <n> keys, 5 locales`.
3. Build the affected client (commands below).
4. Commit.

**Build smoke commands:**
- iOS: `cd apps/ios/native && xcodegen generate && xcodebuild -project LingxiCode.xcodeproj -scheme LingxiCode -configuration StoreDebug -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build` (or the device destination used previously).
- Android: `cd apps/android/native && ./gradlew :app:assembleDebug :app:testDebugUnitTest`

**Step 1: Write the code**

```swift
// LocalizationManager.swift
import Foundation
import SwiftUI

/// Owns the user-selected app language ("" = follow system) and applies it by
/// swizzling Bundle.main's localizedString(forKey:value:table:) so both
/// String(localized:) and SwiftUI Text lookups resolve in the chosen language.
@MainActor
final class LocalizationManager: ObservableObject {
    static let shared = LocalizationManager()
    static let supported: [(code: String, label: String)] = [
        ("", "跟随系统"),
        ("zh-CN", "简体中文"),
        ("zh-TW", "繁體中文"),
        ("en-US", "English"),
        ("ja-JP", "日本語"),
        ("ko-KR", "한국어"),
    ]
    @Published var language: String { didSet { persist(); apply() } }
    private let defaults: UserDefaults
    private static var swizzled = false

    init(defaults: UserDefaults = .standard) {
        self.defaults = defaults
        let stored = defaults.string(forKey: "appLanguage") ?? ""
        self.language = Self.isSupported(stored) ? stored : ""
        Self.swizzleIfNeeded()
        apply()
    }

    static func isSupported(_ code: String) -> Bool { supported.contains { $0.code == code } }

    /// Canonical resource locale for the persisted code ("" => system-derived).
    func effectiveLocale() -> Locale {
        switch language {
        case "zh-CN": Locale(identifier: "zh-Hans")
        case "zh-TW": Locale(identifier: "zh-Hant")
        case "en-US": Locale(identifier: "en")
        case "ja-JP": Locale(identifier: "ja")
        case "ko-KR": Locale(identifier: "ko")
        default: Locale.autoupdatingCurrent
        }
    }

    private func persist() { defaults.set(language.isEmpty ? nil : language, forKey: "appLanguage") }

    private func apply() {
        let id = effectiveLocale().identifier
        UserDefaults.standard.set([id], forKey: "AppleLanguages")
        // refresh any cached bundle selection
    }

    private static func swizzleIfNeeded() {
        guard !swizzled else { return }
        swizzled = true
        let cls = Bundle.self
        let orig = class_getInstanceMethod(cls, #selector(Bundle.localizedString(forKey:value:table:)))!
        let swz = class_getInstanceMethod(cls, #selector(Bundle.lx_localizedString(forKey:value:table:)))!
        method_exchangeImplementations(orig, swz)
    }
}

extension Bundle {
    @objc func lx_localizedString(forKey key: String, value: String?, table tableName: String?) -> String {
        let sel = #selector(Bundle.lx_localizedString(forKey:value:table:))
        // swapped: calling self.sel now calls the ORIGINAL implementation
        let base = self.perform(sel, with: key, with: value, with: tableName) as? String ?? key
        guard tableName == "Localizable" || tableName == nil else { return base }
        return base
    }
}
```

> Note: the swizzle body must forward to the original impl with the *selected* language's bundle. Implement by resolving the language bundle via `Bundle(path: Bundle.main.path(forResource: canonical, ofType: "lproj"))` and falling back to `Bundle.main` when language is "". Verify at runtime that switching to `en` renders English (see Task 7 manual check). If the perform-based forward proves unreliable, use `Bundle.swizzleLocalization(language:)` pattern from the well-known `Localize-Swift` bundle extension (same mechanism, direct IMP call).
