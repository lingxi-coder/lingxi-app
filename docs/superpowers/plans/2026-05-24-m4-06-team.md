# LingXi Core M4 · Plan 06 · Team tools (TeamCreate + TeamDelete)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Multi-commit allowed** — every task ends with its own commit. The verification gate (final task) is the workspace-wide guard.

**Goal:** Ship 2 byte-aligned, hermetic, telemetry-bound team-management tools under `lingxi-code/crates/tools/src/builtin/team.rs` — `TeamCreateTool` (creates `~/.claude/team-mem/<team_name>/config.json`) and `TeamDeleteTool` (removes `~/.claude/team-mem/<team_name>/` with a safety check that warns when the directory contains user memory files). Tag `m4.6` at the end. All wire identifiers from spec §7 (lines 501-507) baked into both production code AND test assertions byte-for-byte. This is the smallest M4 sub-plan: ~8 TDD tasks.

**Architecture:** One new file under `lingxi-tools/src/builtin/`:
- `team.rs` — TWO tools (`TeamCreateTool`, `TeamDeleteTool`) sharing one file per spec §3 module-layout precedent (matches `task.rs` from M4-05). Both tools take input `{ team_name }` and operate on directories under the M3-02 team-mem root `~/.claude/team-mem/<team_name>/`. The root path is computed via `lingxi_memory::memdir::team_paths::resolve_team_memory_dir(home, /* enabled = */ true)` — the M3-02 surface — combined with `home.join(team_name)`. The tools are file-system bound but do not require the `lingxi-memory` watcher: they only need the path constant and the `Arc<dyn FileSystem>` already present in `BuiltinToolContext`.

The two tools depend on:
- `lingxi_memory::memdir::paths::TEAM_MEM_SUBDIR` (M3-02 surface, value `"team-mem"`) — the only public re-export used. We do NOT depend on the watcher or settings gate (`team_memory.enabled`); team-mem creation/deletion is a direct admin action whose precondition is the path constant.
- `lingxi_traits::fs::FileSystem` — already on `BuiltinToolContext.fs: Arc<dyn FileSystem>` (M4-01 lock). Methods used: `create_dir_all(path)`, `write(path, bytes)`, `read_dir(path)`, `remove_dir_all(path)`, `exists(path)`. If any of those are not yet on the trait, Task 0 step 4 documents the additive method (production wraps `tokio::fs`; tests via `MockFileSystem`).
- `lingxi_telemetry::tengu::tool::*` — **6 NEW constants added in Task 2** (3 per tool × 2 tools). The `NAMES` array under `tengu/tool.rs` extends from 88 (post-M4-05; M3-06 baseline 40 + 9 PowerShell/REPL/Sleep from M4-02 + 15 workflow from M4-04 + 24 agent/task from M4-05) to 94. The aggregate `ALL_EVENT_NAMES` count moves up by +6 — Task 2 updates that lock too.

The `BuiltinToolContext` struct (declared in M4-01, extended through M4-02/03/04/05) does NOT grow in this plan: both tools fit the existing `fs + bus + trusted_dirs` surface. The team-mem root is **NOT** a trusted dir in the M4-01 sense (trusted_dirs are the project / cwd allow-list); team-mem is always rooted at `dirs::home_dir()?.join(".claude").join("team-mem")` and is enforced as a path constant inside the tools themselves. Task 0 step 2 adds a single helper `resolve_team_dir(team_name: &str) -> Result<PathBuf, ToolError>` that performs the prefix join.

Per spec §5: tools NEVER self-retry. Filesystem failures surface as `ToolError::Io(std::io::Error::new(ErrorKind::Other, ...))`. Validation failures (bad team name, missing/non-empty on delete) surface as `ToolError::ValidationError(String)` / `ToolError::InvalidInput(String)` per the precedent set by M4-01 (path validation → `ValidationError`) and M4-04 (semantic refusal → `InvalidInput`).

## File touch inventory (locked at top per spec Appendix A convention)

**Creates (new files):**

- `lingxi-code/crates/tools/src/builtin/team.rs` — `TeamCreateTool` + `TeamDeleteTool` + shared helpers:
  - `pub struct TeamCreateTool { fs: Arc<dyn FileSystem>, bus: Arc<AnalyticsBus> }`.
  - `pub struct TeamDeleteTool { fs: Arc<dyn FileSystem>, bus: Arc<AnalyticsBus> }`.
  - Name constants:
    - `pub const TEAM_CREATE_TOOL_NAME: &str = "TeamCreate";`
    - `pub const TEAM_DELETE_TOOL_NAME: &str = "TeamDelete";`
  - Wire-identifier locks (spec §7 lines 501-507):
    - `pub const DEFAULT_TEAM_NAME: &str = "default";`
    - `pub const TEAM_CONFIG_FILENAME: &str = "config.json";`
    - `pub const MAX_TEAM_NAME_LEN: usize = 64;`
    - `pub const TEAM_NAME_PATTERN_DESC: &str = "[a-zA-Z0-9_-]+";` — used in error strings AND parity fixture.
  - Helper functions (private):
    - `fn validate_team_name(name: &str) -> Result<(), ToolError>` — checks length 1..=64, ASCII, every char ∈ `[a-zA-Z0-9_-]`, and that the name does NOT contain `'/'` or `'\\'` or `".."` or `'\0'`. The slash check is redundant with the character-class check but is enforced separately because the error message names "slashes" explicitly when the user-supplied name has them (clearer than "invalid character").
    - `fn resolve_team_dir(home: &Path, team_name: &str) -> PathBuf` — returns `home.join(".claude").join(lingxi_memory::memdir::paths::TEAM_MEM_SUBDIR).join(team_name)`. The use of `TEAM_MEM_SUBDIR` (symbol, not literal) ensures the M3-02 lock is enforced at compile time.
    - `fn home_dir_or_internal() -> Result<PathBuf, ToolError>` — returns `dirs::home_dir().ok_or_else(|| ToolError::Internal("Team: HOME directory not available".into()))`.
  - Input/output bodies are `serde_json::Value` shapes (no per-tool typed input structs — schemas are trivial single-field objects).
  - Error string templates:
    - Empty team name: `"Team: team_name is empty"`.
    - Team name too long: `format!("Team: team_name '{name}' exceeds max length {MAX_TEAM_NAME_LEN}")`.
    - Slash in team name: `format!("Team: team_name '{name}' contains slashes or path traversal")`.
    - Invalid char in team name: `format!("Team: team_name '{name}' contains invalid characters (allowed: {TEAM_NAME_PATTERN_DESC})")`.
    - Already-exists (Create): `format!("TeamCreate: team '{name}' already exists at {path}")` where `{path}` is the team dir.
    - Missing (Delete): `format!("TeamDelete: team '{name}' does not exist at {path}")`.
    - Non-empty warning (Delete, safety guard): `format!("TeamDelete: team '{name}' directory is non-empty ({n} files); pass force=true to delete anyway")` — note `{n}` is the count of files (one-level read_dir).
    - I/O failure (both): `format!("Team: io error at {path}: {err}")`.
  - Input schema — `TeamCreate`:
    ```jsonc
    {
      "type": "object",
      "properties": {
        "team_name": { "type": "string", "minLength": 1, "maxLength": 64 }
      },
      "required": ["team_name"]
    }
    ```
  - Input schema — `TeamDelete`:
    ```jsonc
    {
      "type": "object",
      "properties": {
        "team_name": { "type": "string", "minLength": 1, "maxLength": 64 },
        "force":     { "type": "boolean", "default": false }
      },
      "required": ["team_name"]
    }
    ```
  - Output schema — `TeamCreate`: `{ "team_name": String, "team_dir": String, "config_path": String, "created": Bool }` (note `created=false` is impossible — the tool returns Err if the dir already exists; the field is for forward-compat with an idempotent flag in a later milestone).
  - Output schema — `TeamDelete`: `{ "team_name": String, "team_dir": String, "deleted": Bool, "file_count_at_delete": u64 }`.
  - Flow — `TeamCreateTool`:
    1. Parse `team_name` from `input` via `input.get("team_name").and_then(|v| v.as_str())`; on missing/non-string → `ToolError::InvalidInput("TeamCreate: missing or non-string team_name".into())`.
    2. `validate_team_name(team_name)?` → on Err return the validation error.
    3. Resolve home + team dir: `let home = home_dir_or_internal()?; let team_dir = resolve_team_dir(&home, team_name); let config_path = team_dir.join(TEAM_CONFIG_FILENAME);`
    4. Emit `TEAM_CREATE_STARTED { invocation_id: Verified, team_name: PiiTagged }`.
    5. Existence check: `if self.fs.exists(&team_dir).await { emit TEAM_CREATE_FAILED { error_kind: Verified("AlreadyExists") }; return Err(ToolError::ValidationError(format!("TeamCreate: team '{team_name}' already exists at {team_dir_display}"))); }` where `{team_dir_display}` is `team_dir.display()`.
    6. Create dir: `self.fs.create_dir_all(&team_dir).await.map_err(|e| { emit TEAM_CREATE_FAILED; ToolError::Io(io::Error::new(io::ErrorKind::Other, format!("Team: io error at {}: {e}", team_dir.display()))) })?;`
    7. Build default config JSON: `let config = serde_json::json!({ "team_name": team_name, "schema_version": 1, "created_at_unix_secs": current_unix_secs(&ctx) });` where `current_unix_secs(&ctx)` reads `ctx.clock.now_unix_secs()` (Clock trait from M1 — already on `ToolUseContext`). The schema_version `1` is a LingXi-internal lock for this config format.
    8. Write config: `let body = serde_json::to_vec_pretty(&config).map_err(|e| ToolError::Internal(format!("Team: serde error: {e}")))?; self.fs.write(&config_path, &body).await.map_err(|e| ToolError::Io(io::Error::new(io::ErrorKind::Other, format!("Team: io error at {}: {e}", config_path.display()))))?;`
    9. Emit `TEAM_CREATE_COMPLETED { invocation_id, duration_ms: Verified, team_name: PiiTagged, bytes_written: Verified }`.
    10. Return `ToolCallResult { data: json!({ "team_name": team_name, "team_dir": team_dir.display().to_string(), "config_path": config_path.display().to_string(), "created": true }) }`.
  - Flow — `TeamDeleteTool`:
    1. Parse `team_name` and optional `force` (default false).
    2. `validate_team_name(team_name)?`
    3. Resolve home + team dir.
    4. Emit `TEAM_DELETE_STARTED { invocation_id, team_name: PiiTagged, force: Verified }`.
    5. Existence check: `if !self.fs.exists(&team_dir).await { emit TEAM_DELETE_FAILED { error_kind: "NotFound" }; return Err(ToolError::InvalidInput(format!("TeamDelete: team '{team_name}' does not exist at {team_dir_display}"))); }`
    6. Safety check (when `force == false`): read directory, count non-config entries; if any user files present (anything other than `config.json`) → emit `TEAM_DELETE_FAILED { error_kind: "NonEmpty" }`; return `Err(ToolError::ValidationError(format!("TeamDelete: team '{team_name}' directory is non-empty ({n} files); pass force=true to delete anyway")))`. The "warn" semantics from the user prompt are implemented as a hard refusal that prompts the caller to opt in via `force` — strictly safer than a soft warning (precedent: M4-04 destructive tools refuse and require explicit opt-in).
    7. Remove dir: `self.fs.remove_dir_all(&team_dir).await.map_err(|e| ToolError::Io(io::Error::new(io::ErrorKind::Other, format!("Team: io error at {}: {e}", team_dir.display()))))?;`
    8. Emit `TEAM_DELETE_COMPLETED { invocation_id, duration_ms, team_name: PiiTagged, file_count_at_delete: Verified }`.
    9. Return `ToolCallResult { data: json!({ "team_name": team_name, "team_dir": team_dir.display().to_string(), "deleted": true, "file_count_at_delete": n }) }`.
  - Tool metadata for both:
    - `TeamCreateTool`: `name() = TEAM_CREATE_TOOL_NAME`, `aliases() = &[]`, `is_concurrency_safe(_) = true` (independent team_names never collide), `is_read_only(_) = false`, `is_destructive(_) = false`, `is_open_world(_) = false`, `interrupt_behavior(_) = InterruptBehavior::Block` (filesystem write should run to completion or fail), `max_result_size_chars() = 4096`.
    - `TeamDeleteTool`: `name() = TEAM_DELETE_TOOL_NAME`, `aliases() = &[]`, `is_concurrency_safe(_) = true`, `is_read_only(_) = false`, `is_destructive(_) = true` (removes user data), `is_open_world(_) = false`, `interrupt_behavior(_) = InterruptBehavior::Block`, `max_result_size_chars() = 4096`.

**Critical fidelity notes (divergences from the user prompt, locked here):**

- **Safety check on Delete**: user prompt says "warn if non-empty". Implemented as a HARD REFUSAL with an explicit `force: bool` opt-in (precedent: M4-04 destructive tools). The error string templated above carries the file count and the opt-in hint. The integration test for the non-empty path asserts the directory is still present after the refused call.
- **Team name validation**: user prompt says "no slashes, max length 64, `[a-zA-Z0-9_-]+`". Implemented with TWO separate checks — slash detection emits a slash-specific error (clearer UX); character-class check covers everything else. Both errors are byte-locked in the parity fixture.
- **`config.json` initial body**: user prompt does not specify a body. We write `{ "team_name": <name>, "schema_version": 1, "created_at_unix_secs": <secs> }` (pretty-printed via `serde_json::to_vec_pretty`). The `schema_version: 1` is a LingXi-internal lock; bumped only when the config schema changes.
- **`team_memory.enabled` settings gate**: spec §7 says "(M3-02 lock)" — the M3-02 watcher path resolution gates on `team_memory.enabled`. Admin create/delete actions in M4-06 do NOT consult that gate (an admin must be able to provision team-mem even if the user has not yet opted in to watching). This divergence is documented in the parity fixture `_note`.
- **Tool event suffix**: user prompt says `_completed`; M3-06 lock is `_completed` (matches). Spec §1 shorthand `_succeeded` is NOT the wire string.

//! Team-management builtin tools (`TeamCreate`, `TeamDelete`).
//!
//! LingXi-internal feature with no upstream `claude-code/src/tools/`
//! counterpart. Both tools operate on the M3-02 team-mem root
//! `~/.claude/team-mem/<team_name>/`. The `config.json` body is a LingXi

use std::sync::Arc;

use lingxi_memory::memdir::paths::TEAM_MEM_SUBDIR;

use lingxi_traits::fs::FileSystem;

// -- Wire identifier locks (spec §7 lines 501-507) ---------------------------

/// Tool name for the `TeamCreate` builtin.
pub const TEAM_CREATE_TOOL_NAME: &str = "TeamCreate";

use lingxi_tools::tool_trait::ToolError;

/// Validate a team name per spec §7 + plan locks.
///
/// Rules:
/// - non-empty
/// - length <= [`MAX_TEAM_NAME_LEN`] bytes
/// - no `/`, `\`, `..`, or `\0`
/// - all chars in `[a-zA-Z0-9_-]`
///
/// Each failure produces a byte-locked error string (see
/// `parity/fixtures/team_tools.json`).
pub(crate) fn validate_team_name(name: &str) -> Result<(), ToolError> {
    if name.is_empty() {
        return Err(ToolError::ValidationError(
            "Team: team_name is empty".into(),
        ));
    }
    if name.len() > MAX_TEAM_NAME_LEN {
        return Err(ToolError::ValidationError(format!(
            "Team: team_name '{name}' exceeds max length {MAX_TEAM_NAME_LEN}"
        )));
    }
    // Slash / traversal check FIRST so its error string is more specific
    // than the generic "invalid characters" message.
    if name.contains('/') || name.contains('\\') || name == ".." || name.contains("..") {
        return Err(ToolError::ValidationError(format!(
            "Team: team_name '{name}' contains slashes or path traversal"
        )));
    }
    for ch in name.chars() {
        let ok = ch.is_ascii_alphanumeric() || ch == '_' || ch == '-';
        if !ok {
            return Err(ToolError::ValidationError(format!(
                "Team: team_name '{name}' contains invalid characters (allowed: {TEAM_NAME_PATTERN_DESC})"
            )));
        }
    }
    Ok(())
}

                format!("Team: io error at {}: {e}", config_path.display()),

            lingxi_telemetry::tengu::tool::TEAM_CREATE_COMPLETED,
            done_meta,
        ).await;

            data: json!({
                "team_name": team_name,
                "team_dir": team_dir.display().to_string(),
                "config_path": config_path.display().to_string(),
                "created": true,
