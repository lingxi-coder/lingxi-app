# M6-06 Engine Wiring 1 — Real Cost Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `OrchestratorHandle::snapshot_cost` stub (returns zeros) with a real read from `lingxi_cost::CostTracker` (M3-05). Construct one `CostTracker` per process in `lingxi-cli::init::build_runtime`, share it with the orchestrator, record each successful `messages_create` round-trip through `CostTracker::record_api_response_v2`, and surface the cumulative dollars via the existing `/cost` slash command (M5-11 template — unchanged) and a 4-decimal `$0.0234` placeholder slot the M6-02 StatusLine already renders. After M6-06 the StatusLine cost stops being `$0.000` and the `/cost` line stops being all zeros for the first time.

**Architecture:** `ConversationOrchestrator` grows two new optional fields: `cost_tracker: Option<Arc<CostTracker>>` and `session_started_at: Instant`. A builder method `with_cost_tracker(Arc<CostTracker>)` wires them in. After every successful `execute_one_turn` API response, `turn_loop.rs` translates `MessageResponse.usage` → `lingxi_cost::Usage`, looks up the provider via `OrchestratorConfig::model`, and calls `tracker.record_api_response_v2(...)`. The trait method `snapshot_cost()` reads `tracker.snapshot()` (now a `CostState`) and projects it onto the locked `CostSnapshot` shape (`total_usd = nano_usd as f64 / 1e9`, `input_tokens = Σ entry.usage.tokens.input`, `output_tokens = Σ entry.usage.tokens.output`, `api_calls = Σ entry.usage.api_call_count`, `session_duration = Instant::now() - session_started_at`). The `lingxi-cli::init` constructs one `(CostTracker, persist_tx)` pair, spawns a background drain task that discards snapshots (M6 does not persist cost — M7 wires a `~/.config/lingxi/cost-state.json` writer), and threads the `Arc<CostTracker>` into the orchestrator via the new builder. The TUI `StatusLine` from M6-02 already reads `cost: lingxi_traits::Money` from props; M6-06 just bumps the format string from `"${:.3}"` to `"${:.4}"` (claude-code parity) and removes the placeholder branch — once `snapshot_cost` returns real numbers, the same prop pipeline lights up. `/cost` (M5-11) is untouched at the handler level — the template `"Cost: ${total:.4} ({calls} calls, {input}+{output} tokens, {dur} session time)"` already reads from `CostSnapshot`; M6-06 verifies the data flow with a behaviour test rather than changing rendering code.

**Tech Stack:** Rust 2021, `lingxi-cost = { path = "../cost" }` (M3-05 — already a workspace crate), `lingxi-protocol::SessionId` (existing), `tokio = "1"` (`mpsc::channel`, `tokio::sync::RwLock`, `tokio::time::Instant`), `lingxi-telemetry::AnalyticsBus` (existing — passed through `record_api_response_v2`), `lingxi-traits::{CostSnapshot, OrchestratorHandle}` (locked since M5-11). No new dependencies.

**Locked Types (deviation from prompt note):**
- The prompt's "LOCKED TYPES" line specified `CostSnapshot { total_usd: f64, by_model: HashMap<ModelId, ModelCost>, total_input_tokens: u64, total_output_tokens: u64, total_duration: Duration }`. The **actual** `lingxi_traits::CostSnapshot` (locked since v0.6.0 in M5-11) is the leaf-friendly mirror: `{ session_id, total_nano_usd, total_tokens, total_usd, input_tokens, output_tokens, api_calls, session_duration, .. }` — **no `by_model: HashMap<…>` field**, **no `ModelCost` type**. This plan KEEPS the v0.6.0 trait surface unchanged (zero parity-fixture regression). Per-model breakdown is rendered from `CostState.per_model_usage` only inside the `lingxi-cost` crate's own helpers; the `/cost` command's locked M5-11 template does NOT show per-model breakdown either (just totals). A real per-model render-path lands in M7 alongside the StatusLine "expanded cost" overlay. The prompt's "per-model breakdown" deliverable item is therefore reduced to "the underlying `CostState` carries `per_model_usage` and is reachable via a new `pub fn cost_state(&self) -> Option<CostState>` accessor on `ConversationOrchestrator` for future M7 use" — the user-visible `/cost` line remains the M5-11 totals-only template.

1. **`CostSnapshot` shape mismatch with prompt.** The prompt's "LOCKED TYPES" line specified a per-model `HashMap<ModelId, ModelCost>` field that does NOT exist on `lingxi_traits::CostSnapshot` (verified by reading `crates/traits/src/orchestrator.rs:27-49`). The v0.6.0 trait surface is a flat totals-only struct. M6-06 keeps it that way — adding a per-model HashMap would force a trait surface change and break the locked M5-11 `/cost` template (which renders totals only) and the v0.6.0 parity fixtures. Per-model state IS reachable via the new `ConversationOrchestrator::cost_state() -> Option<CostState>` accessor for M7's "expanded cost" overlay. **Recommendation:** explicitly document this in the v0.7.0 release notes and defer the per-model display to M7 alongside the `/cost --detail` flag.

2. **Telemetry bus not wired.** `CostTracker::record_api_response_v2` accepts `bus: Option<&Arc<AnalyticsBus>>` and emits `tengu_cost_recorded` when `Some`. M6-06 passes `None` because the orchestrator does NOT currently carry an `AnalyticsBus` field. As a result the `tengu_cost_recorded` event does NOT fire in v0.7.0 production. The parity_cost_events test-harness fixture (which exercises the M3-05 emitter directly) still passes — that test does NOT go through the orchestrator. M7 should add an `AnalyticsBus` field to `ConversationOrchestrator` and pass it through here. Filed as M7 work item.

3. **`Duration::ZERO` for `record_api_response_v2`.** The api-client adapter does not currently expose wall-clock duration for individual `messages_create` calls. M6-06 passes `Duration::ZERO` so `CostState.total_api_duration_ms` will read `0` even after many turns. This is acceptable for the `/cost` display (which exposes `session_duration` from `session_started_at.elapsed()`, NOT `total_api_duration_ms`), but it does make the on-disk persisted `CostState` slightly inaccurate. M7 should thread a `tokio::time::Instant::now()` wrapper around the `messages_create` call to capture real call duration.

4. **`retries = 0` always.** Same provenance as (3) — the api-client adapter swallows retries internally. M6-06 records `retries = 0`, meaning the `total_api_duration_without_retries_ms` field of `CostState` will equal `total_api_duration_ms` even when retries happened. Acceptable v0.7.0 imprecision; M7 fix.

5. **Cost-state persistence dropped.** The drain task in Task 6 Step 4 discards every snapshot. This means closing and reopening `lingxi-cli` starts cost back at $0.0000. claude-code's behaviour is the same (its `cost-tracker.ts` is per-process), so this is arguably correct claude-code parity rather than a gap. If the user wants cross-session cost accumulation (NOT a claude-code behaviour), M7 would need a `~/.config/lingxi/cost-state.json` writer + a `--resume` cost-restoration code path.

6. **Streaming SSE path not exercised by tests.** Tasks 3 and 4 wire the cost recording in `execute_one_turn` (the batched path). The streaming path (`run_turn_streaming` → `try_run_turn_streaming` in `conversation.rs:533-557`) also calls `snapshot_cost_real` at `emit_end_turn` (Task 5 retired the old helper for both paths), but the **recording** of usage from streaming responses happens via a different code path (the SSE `message_delta` event carries the final `usage` payload). If streaming is the default mode in v0.7.0 (it is NOT in v0.6.0 — `new_with_streaming` is opt-in), Task 3's recording call may not fire. M6-06 assumes batched (M6-02 uses `run_turn`, not `run_turn_streaming`). If M6-03 wires streaming by default in the TUI, a follow-up task in M6-03 must mirror Task 3's recording block into the streaming `message_delta` handler.
