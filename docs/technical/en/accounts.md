# Models and API keys

Connect the model provider you want to use. Keys stay in the credential store on this computer.

<a id="your-provider"></a>

## You choose the provider

LingXi sends each request through a provider account on this computer. Adding an account does not create a LingXi subscription, and the key is not a LingXi password.

<a id="add-key"></a>

## Add an API key

Pass the key on standard input, or point at a slot that is already in this computer’s secure store. The command does not accept the key as an argument, and it does not print the key back.

### Add a key from stdin

```shell
printf %s "$API_KEY" | lingxi provider accounts add PROVIDER --name WORK --api-key-stdin
```

<a id="oauth"></a>

## Sign in with the provider

Providers that support OAuth use login. The command can print the address instead of opening a browser, and a remote shell can paste the callback address on stdin.

### Start provider login

```shell
lingxi provider accounts login PROVIDER --name WORK
lingxi provider accounts list PROVIDER
```

<a id="choose-model"></a>

## Choose a model

In a session, /model lists the models you can use. On the command line, --model sets the model for that launch. The selection is saved as model in ~/.lingxi/settings.json, and recent choices are kept in recentModels.

A managed policy can hide models. A normal install has no such list, so the picker shows the models the providers offer.
