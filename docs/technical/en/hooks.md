# Hooks

A hook is a command, HTTP call, or MCP tool that runs when a session event happens.

<a id="where"></a>

## Where hooks are configured

Put a hooks object in settings.json. Each key is an event name. Each entry can filter with a matcher and then lists hooks. A hook type is command, http, or mcp_tool. A command hook runs a program. An HTTP hook calls a URL. An MCP hook calls a tool on a connected server. Unknown event names and entries that omit their required fields are skipped.

/hooks shows the hook configuration for tool events. Config changes are reported separately for ~/.lingxi/settings.json, the checked-in .lingxi/settings.json, the gitignored .lingxi/settings.local.json, managed policy, and skills. Policy changes are not something a hook can block.

### A command hook

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [{ "type": "command", "command": "echo session-started" }] }
    ]
  }
}
```

<a id="events"></a>

## Events you can subscribe to

The loader accepts the event names below. A hook on PreToolUse runs before a tool call. PostToolUse runs after a successful call, PostToolUseFailure after a failed one, and PostToolBatch after the batch. UserPromptSubmit runs when you send a prompt. SessionStart and SessionEnd wrap the session. Stop and StopFailure wrap a stop. PermissionRequest and PermissionDenied wrap an ask. PreCompact and PostCompact wrap context compaction. SubagentStart and SubagentStop wrap a subagent that has already been spawned. AgentSpawn runs before that spawn and may refuse it or change the agent, model, directory, or background flag.

Other names you can use are InstructionsLoaded, ConfigChange, Notification, FileChanged, CwdChanged, and DirectoryAdded. --safe-mode skips settings hooks. --bare skips them too. A managed policy can limit hooks to the managed set.
