# SDKs & libraries

Build with LingXi. Connect models, orchestrate agents, and bring a Linux runtime to mobile — with a toolkit that fits your application.

## Find your starting point

The SDKs form distinct layers. Use LLM Client for direct model calls, Harness Runtime for the agent loop, and Mobile Linux for local execution on Android and iOS.

- [LLM Client](llm-client.md)

<a id="sdk-map"></a>

## At a glance

Three independent SDK repositories, plus the TypeScript bridge and native host integration in the product repository. The API index links byte-identical committed files to their exact revision and marks changed files as working-tree sources.

| SDK / integration | Responsibility | Entry points |
| --- | --- | --- |
| Harness Runtime | Agent loop, sessions, tools, permissions and lifecycle | Rust facade; desktop/mobile/headless |
| LLM Client | Model protocols, transport, streams and provider services | Rust LingxiClient |
| Mobile Linux | Local execution, PTY and verified resources | Rust contracts, Kotlin/Swift facade |
| Product Bridge | Product host transport and client DTOs | Private Node.js client and native FFI |

<a id="integration"></a>

## Build your integration

- Connect models: choose LLM Client and configure your own provider credentials.
- Run agents: provide Harness Runtime with a session runtime and host lifecycle.
- Execute on mobile: use the Rust API or Android / iOS native wrappers.
- Integrate the LingXi product: use its private bridge and platform wrappers within the product build.

<a id="source"></a>

## Source & versioning

Examples are grounded in the current repositories. Git dependencies should be pinned to a reviewed revision. Native installation and runtime constraints are described on each platform page.

The bridge is an internal Node.js package. Rust crates are not Python or npm SDKs; CLI package installers install the application, not these libraries.
