# Sessions

Continue the latest session, pick an older one, or keep working from a copy.

<a id="continue"></a>

## Continue or pick one

lingxi --continue opens the latest session in this directory. lingxi --resume opens a picker, and lingxi --resume SESSION_ID opens that session. Inside a session, /resume does the same job. /clear starts a fresh context and leaves the previous session on disk, so /resume can still open it.

### Continue, resume, or branch

```shell
lingxi --continue
lingxi --resume
lingxi --resume SESSION_ID --fork-session
```

<a id="fork"></a>

## A copy with a new id

--fork-session keeps the history you resumed and stores the new work under a new session id. With agent view on, which is the default, /fork copies the conversation into a background session and leaves you in the current one. /subtask sends a subagent out with this conversation and brings the result back here. It needs a task, and it waits until the first turn has happened.

Agent view turns off when settings set disableAgentView to true, or when LINGXI_DISABLE_AGENT_VIEW is 1, true, yes, or on. In that mode /fork starts the subagent inside this session, and /subtask is not the spawn command.

- [Subagents](subagents.md)
- [Environment variables](environment.md)

<a id="background"></a>

## Background sessions

lingxi --bg starts the work as a background session and returns to the shell. It cannot be combined with --print. lingxi agents lists those sessions in a terminal; add --json when stdout is not a terminal. lingxi stop keeps the conversation. lingxi attach opens it again, and lingxi --resume works after it has stopped. lingxi rm deletes that background session and its worktree.

### Start, stop, and reopen

```shell
lingxi --bg "Run the test suite and summarize failures"
lingxi agents
lingxi stop SESSION_ID
lingxi attach SESSION_ID
```

The program name in help text is lingxi-cli. After the npm package is installed, the same program is the lingxi command.
