# Settings files

User settings live in the config directory. Project settings live in the repository. They do not merge the same way for every key.

<a id="files"></a>

## The files

When LINGXI_CONFIG_DIR is unset, the config directory is ~/.lingxi and the global file is ~/.lingxi.json. When it is set to a non-empty path, session settings are read from that directory. An empty value is still set for the command line: it is a relative path, so the CLI resolves it from the directory where you started LingXi. /doctor prints the config directory value it is using. The ~/.lingxi.json lookup treats an empty LINGXI_CONFIG_DIR as unset.

| File | What it is for |
| --- | --- |
| ~/.lingxi/settings.json | Your settings, including model and permissions.defaultMode. |
| .lingxi/settings.json | Project settings that can be committed. |
| .lingxi/settings.local.json | Project-local settings. Git ignores this file. The permission-mode reader below does not load it. |
| ~/.lingxi.json | A separate global file. It is not settings.json. |

- [First session](first-session.md#config-home)

<a id="permission-mode"></a>

## How the permission mode is chosen

For the permission mode, the CLI reads the user settings.json and then the project .lingxi/settings.json. The project value wins for permissions.defaultMode. If either file disables bypass or auto, that disable stays on. Only the user file can grant auto or bypassPermissions. A project file that asks for those modes does not grant them.

--settings FILE_OR_JSON is applied after those files and still applies when --restricted is set. --setting-sources user,project,local chooses which ambient files this reader opens. With no flag, it reads user and project. --restricted reads neither. This reader does not open settings.local.json. Other keys, including hooks, have their own files and are not merged by this same rule.

### Plan mode in your user settings

```json
{
  "permissions": { "defaultMode": "plan" }
}
```
