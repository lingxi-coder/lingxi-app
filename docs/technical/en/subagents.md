# Subagents

Define a subagent with a Markdown file, or ask LingXi to write one. /agents is not a manager.

<a id="files"></a>

## Definition files

Put one Markdown file for each subagent under .lingxi/agents/ in the project, or under ~/.lingxi/agents/ for every project. Nested directories are included. LingXi walks from the current directory up toward the project root and stops at your home directory. On the same agent name, the deeper project file wins over a shallower one, and a project file wins over the user file. --add-dir can add more project directories at a lower priority than the walk.

/agents prints instructions. It tells you to ask LingXi to create or update a subagent, or to edit those directories. It does not open a manager. lingxi agents is a different command: it lists background sessions.

- [Sessions](sessions.md#background)

<a id="launch"></a>

## Choose one for a launch

--agent NAME selects the agent for this launch and overrides the agent setting. --agents takes one JSON object that defines agents for this launch. Those definitions sit above the files on disk. Safe mode warns and ignores that JSON.

With agent view on, /subtask is how you send a subagent from the session. With agent view off, use /fork for that in-session spawn. Caps you can set are LINGXI_MAX_CONCURRENT_SUBAGENTS, LINGXI_MAX_SUBAGENT_SPAWN_DEPTH, and LINGXI_MAX_SUBAGENTS_PER_SESSION. LINGXI_SUBAGENT_MODEL is the default model when a call does not name one. LINGXI_SUBAGENT_MODEL_FORCE stops a call from picking a different model.
