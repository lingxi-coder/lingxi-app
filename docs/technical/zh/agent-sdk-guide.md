# 选择 Agent 集成方式

将熟悉的 Agent SDK 概念对应到灵犀实际的 Rust 运行时、模型客户端与产品协议，选择适合任务的集成层。

<a id="pick-the-layer"></a>

## 从你要完成的操作出发

直接模型请求不会替你在文件系统执行工具调用。Harness 通过宿主组合提供 Agent 循环；公共门面访问已存在会话，并不充当进程启动器或托管服务。

| 应用需要 | 选用 | 你需要提供 |
| --- | --- | --- |
| 调用模型或消费模型增量 | LLM Client | 供应商配置、请求、凭据和响应处理。 |
| 在 Rust 宿主中运行会调用工具的 Agent | Harness Runtime | 已组装运行时、输出目标、权限 gate 和生命周期负责人。 |
| 为既有灵犀宿主构建界面 | ClientCommand／ClientEvent 与产品 Bridge | 可信传输、命令分发、事件呈现和交互回复。 |
| 在 Android／iOS 运行命令或 PTY | Mobile Linux Runtime | 经过验证的资源、平台路径与进程归属。 |

<a id="concept-map"></a>

## 先对应概念，再迁移代码

| 熟悉的概念 | 灵犀集成点 | 迁移时的决定 |
| --- | --- | --- |
| 运行 Agent query | SessionHandle::run(RunInput, CancellationToken) | 先提供已组装会话；区分终态 Result 和流式输出。 |
| 迭代助手／工具消息 | OutputStream 或 AdapterOutputStream → ClientEventSink | 首次 run 前在组合阶段安装输出目标。 |
| 恢复／分支对话 | ResumeSession；MobileHost 上的 ForkSession | Resume 确认会话已挂载；MobileHost 的 Fork 确认分支已创建，向该分支提交任务前还需挂载返回的新标识。当前 Desktop Bridge 未接通 ForkSession。 |
| 批准工具调用 | PermissionGate；协议宿主可用 AdapterPermissionGate | 使用 request_id 将真实用户决定交给请求所属执行。 |
| 工具、Skills、Hooks 与 MCP | 宿主拥有的注册表及生命周期 | 在实际发行组合中核对激活与依赖。 |

本表是灵犀 Rust API 的使用流程。其他语言绑定里的选项对象、导入路径和认证方式不能代替这些 Rust 类型。

<a id="host-contract"></a>

## 先写清宿主契约

1. 选择 desktop、mobile 或注入的 SessionService／LifecycleService 实现，并确认所需 feature 和原生资源。
2. 确定文本、工具、问题、权限与终态的交付位置；相关适配器应使用一致的连接／会话归属。
3. 准入工作前设置工作目录、工具范围、供应商／模型及凭据归属。
4. 轮次取消并等待清理，与应用退出时排空宿主，应分别处理。

<a id="migrate-one-slice"></a>

## 迁移一条完整交互

- 先实现纯文本轮次，覆盖正常结束与失败；再接流式呈现和一个需要审批的工具。
- 迁移选项的意图而非名称。模型选择、工具允许列表与会话继续，应进入对应宿主服务，而非凭空增加 RunInput 字段。
- 扩大迁移范围前，在目标宿主核对图像、工具结果、审批取消、追问上下文与关闭。
