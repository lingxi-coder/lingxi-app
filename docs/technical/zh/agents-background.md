# 子 Agent 与后台任务

区分前台与脱离前台工作中的 Agent 池准入、任务归属、邮箱交付与终态发布。

<a id="agent-boundary"></a>

## Agent 上下文与准入

Agent 携带定义、解析模型／profile、允许工具、工作上下文、取消和父级归属。池准入执行容量限制，而不是假设无限并发。子权限模式由可信父级／定义事实与策略派生，模型参数不能制造更大权限。

主编排器与子 Agent runner 共享供应商及工具契约，但使用独立历史和输出投影。agent_id、task_id、session_id 与供应商请求 ID 应分开。子 Agent 对话行保留消息标识，包括部分流和终态错误证据。

<a id="background-composition"></a>

## 后台执行需要宿主装饰器

Desktop 的 background_agent 是实际 async-agent 装饰器。它将 Agent run_in_background 转为持久 LocalAgent task，安装邮箱并把 SendMessage 推向任务恢复。裸池 spawner 对未接通的脱离前台准入报告错误；仅构建池并不会提供持久后台执行。

TaskRegistry 负责长期工作的状态、输出和取消。宿主路由生命周期／进度通知并单次发布终态结果。调用方脱离或前台面板关闭时，不能静默丢失任务负责人或持久回执。

<a id="mailbox-and-observer"></a>

## 消息、观察者与停驻 Agent

邮箱交付与模型执行是不同阶段。宿主接受消息并不证明接收方模型已消费它。运行时 Agent 列表与对话加载投影共享状态；observer guard 防止过期负责人或替换会话的输出进入当前对话。

停驻 Agent 保留可恢复状态，而不是被视为永久运行。恢复必须在准入前重建会话归属、工具授权和邮箱关联。没有活动或恢复负责人的 Agent 记录并非可执行后台任务。

<a id="failure-and-cancel"></a>

## 失败、容量与取消

准入饥饿、供应商失败和工具失败分别报告。取消经 task／agent 负责人传播；释放 lease 前收集最终对话并清理输出。供应商失败时可保留部分已输出响应，同时终态 task 状态仍记录失败。

Coordinator／teammate 行为由选定组合、共享注册表和传输启用。桌面进程内及 pane teammate 有各自宿主生命周期。不能仅由 collaboration Cargo feature 推断跨设备协作或移动端等价能力。

<a id="agent-checks"></a>

## 验证准入与负责人清理

- 测试池容量、排队取消、前台脱离、邮箱恢复、部分输出保留及终态发布重试。现有单元／fixture 检查不代表多供应商真实行为已验收。
- 在实际桌面系统验证 pane 进程、工作空间清理与外部任务副作用。冷重启验收必须证明负责人已恢复，不能只展示持久 task 列表。
