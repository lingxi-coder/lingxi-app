# API 参考

<a id="find-api"></a>

## 从你要完成的任务开始

集成一个能力需要的不只是类型签名。先选择要完成的任务：指南会说明如何构造输入、消费事件或返回值、管理资源，以及处理失败。

| 任务 | 重点接口 | 指南解决的问题 |
| --- | --- | --- |
| 运行 Agent | HarnessBuilder、SessionService、RunInput | 宿主服务、会话、单轮执行、流事件与关闭 |
| 调用模型 | ChatRequest、RequestOptions、ChatResponse | 供应商选择、请求凭据、响应正文与错误 |
| 构建流式界面 | ModelStream、StreamEvent | 增量、最终输出、取消与结构化结果 |
| 在移动端执行命令 | LinuxCommandRequest、LinuxProcessHandle | 启动、工作目录、输出、标准输入、退出与宿主生命周期 |

## 检索 API 声明

输入类型或方法名，再按 SDK 缩小范围。打开源码可查看完整定义；编译器生成的 Rustdoc 位于下方可展开的源码与构建配置中。

<a id="api-failures"></a>

## 接入失败时从哪里排查

| 现象 | 先检查 |
| --- | --- |
| 找不到类型或方法 | 实际依赖的源码版本、Cargo feature、导入路径和 Rustdoc 中的签名 |
| 请求在产生输出前失败 | 选中的供应商或连接、每次请求的凭据和返回的错误类型 |
| 模型已空闲，Agent 仍在等待 | 待处理权限或问题事件、工具完成情况，以及宿主是否持续消费事件 |
| 移动端命令找不到文件 | Guest 可见路径、cwd、挂载与 rootfs 就绪状态，区分宿主文件系统路径 |
