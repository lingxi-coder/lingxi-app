# 构建、签名与发行流程

构建各产品入口，区分依赖检查、签名打包、静态产物与已发布版本。

<a id="rust"></a>

## CLI 与 Bridge

Cargo 包选择以产品清单为准。CLI npm/PyPI 包装分发应用，不代表独立 Rust SDK。发行工作流身份与目标产物需要共同审查，本地二进制构建成功不等于包已发布。

### 锁定依赖的产品构建

```sh
cd lingxi-app
cargo build --locked -p cli --release
cargo build --locked -p bridge-server --bin bridge-server
npm --prefix packages/bridge-client ci
npm --prefix packages/bridge-client run build
```

验证方式: 需环境验证

<a id="macos"></a>

## 签名 macOS 应用

使用仓库打包包装器，由它协调 Bridge、Electron、原生 helper、Credential Broker、描述文件、由内向外签名及包内静态/运行检查。凭据持久化需要签名开发通道；未打包的 npm run dev 进程不能作为等价验收环境。

### 签名预检与打包启动

```sh
cd lingxi-app/apps/electron
npm run package:mac:flare -- --check
npm run package:mac:flare -- --launch
```

验证方式: 需环境验证

描述文件与签名操作可能改变开发者账户或设备注册状态。本次文档编写不运行打包或发行命令。

<a id="mobile"></a>

## 原生包与资源

Android 构建组合 Rust FFI、原生执行资源、生成 Kotlin 绑定与 Gradle。iOS 构建组合 Rust 静态库/XCFramework、生成 Swift 绑定、原生资源与 Xcode 工程。设备测试前应检查 ABI 切片、SDK/rootfs 来源和绑定身份。

- [Android 集成](mobile-android.md)
- [iOS 集成](mobile-ios.md)

<a id="website"></a>

## 官网与编译器文档

Rustdoc 构建保留在忽略的输出目录。开发服务器与静态构建检查产物可用性：即使保存的记录标为 ready，缺少对应文件的文档包也不会提供链接。静态网站构建提供文档与资源，不部署 Agent API，也不执行发行发布。官网发布属于另外的授权操作。

### 文档构建

```sh
cd lingxi-app/apps/web
npm run docs:sync
npm run docs:check
npm run docs:examples
npm run docs:rustdoc
npm run typecheck
npm test
npm run build
```

验证方式: 需环境验证

<a id="checklist"></a>

## 发行证据

1. 记录各 SDK/源码 revision 与产物校验和。
2. 验证要求的 feature 与 ABI 组合，明确不可用目标，不推定支持。
3. 按平台工作流检查生成资源、签名和包内行为。
4. 发行审查通过后发布，再核对远端发行身份与产物。
