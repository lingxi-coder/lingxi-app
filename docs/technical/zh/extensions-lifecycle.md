# 工具、Skills、Hooks、MCP 与 LSP

经可信注册表发现扩展，并在激活、更新、调用和清理过程中保持权限归属。

<a id="extension-kinds"></a>

## 扩展职责

| 接口 | 运行时职责 |
| --- | --- |
| 工具 | 规范操作、schema、启用、调用权限、调度提示、进度与结果。 |
| Skill／命令 | 发现的指令内容与调用语义。Skill 不是独立供应商网络传输。 |
| Hook | 配置的事件行为，可注入上下文、约束决策或执行宿主动作。 |
| 插件 | 经过校验的包贡献，涵盖工具／命令／Agent／skill／hook／MCP／LSP／workflow 注册表。 |

<a id="discovery-activation"></a>

## 发现并单次激活

桌面组合加载适用命令／skills，使用共享注册表构建生产 PluginManager。ToolRegistry 以确定性分区声明内置与动态来源。能力到达模型前，会话允许列表、工具池选择、插件信任与 managed 限制均参与控制。

包 manifest 可以声明组件，但不能证明激活成功。应检查加载状态与诊断。Reload 更新所属分区而不是复制能力；Disable 清理贡献组件，清理未完成时保留明确失败状态。

<a id="hook-flow"></a>

## Hooks 与带权限的调用

事件包括 PreToolUse、PostToolUse、PostToolUseFailure、SessionStart／End、PermissionRequest、TaskCompleted、ConfigChange 和 PostToolBatch。Command、HTTP、prompt 与 agent executor 的依赖和错误语义不同。使用 executor 注册表，不在 UI 客户端自行解释 hook JSON。

Hook 输出经过共享 response 契约解析，可能影响调度／上下文。HTTP hook 应用显式 SSRF guard。Hook 发起的 MCP 调用使用已活动 MCP 注册表；桌面延迟绑定 bridge 避免构建循环，并不赋予 hook 独立发现服务器的权限。

<a id="mcp-and-lsp"></a>

## MCP 与 LSP 生命周期

McpRegistry 负责连接、认证状态、启动加载、目录更新和重连／退避。对应宿主传输提供 stdio、HTTP、SSE 或 WebSocket；移动端使用独立注入传输。断开的服务器是带诊断状态的不可用服务，不是成功的空目录。Elicitation 与 input-required 状态经宿主请求路由返回。

LSP 注册只接收已验证插件服务器；用户／项目设置不能注入任意 LSP 服务器。注册表追踪激活、连接与重启策略（默认最多三次重启）。移动端 Auto／Off／On 激活使用可信工作空间分类与 Mobile Linux 传输，原生进程可用性仍是前提。

<a id="extension-checks"></a>

## 可重复生命周期检查

1. 使用显式 fixture 验证发现，激活后检查声明的规范名称，并执行一次受权限控制调用。
2. 模拟传输断开与目录更新，确认旧工具消失，等待请求以对应失败结束。
3. 禁用插件，检查所属进程清理并重试保留的清理失败。真实第三方进程与 OAuth 单独验收。

验证方式: 需环境验证

这些命令定位现有契约，不认证远端服务器行为或第三方插件。验收记录应包含外部服务版本与目标宿主证据。
