# Hooks

Hook 是在会话事件发生时运行的命令、HTTP 调用或 MCP 工具。

<a id="where"></a>

## 配置写在哪里

在 settings.json 里写 hooks 对象。每个键是事件名。每一项可以用 matcher 过滤，然后列出 hooks。类型是 command、http 或 mcp_tool。command 运行一个程序，http 调用一个 URL，mcp_tool 调用已连接服务器上的工具。不认识的事件名，以及缺少必填字段的条目，会被跳过。

/hooks 显示工具事件的 hook 配置。配置变更会按来源分开报告：~/.lingxi/settings.json、已纳入版本库的 .lingxi/settings.json、被 git 忽略的 .lingxi/settings.local.json、托管策略，以及 skills。策略变更不能被 hook 拦住。

### 一个命令 hook

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [{ "type": "command", "command": "echo session-started" }] }
    ]
  }
}
```

## 可以订阅的事件

加载器接受下面这些事件名。PreToolUse 在工具调用前运行。PostToolUse 在成功之后，PostToolUseFailure 在失败之后，PostToolBatch 在一批调用结束之后。UserPromptSubmit 在你发出提示时运行。SessionStart 和 SessionEnd 包住会话。Stop 和 StopFailure 包住一次停止。PermissionRequest 和 PermissionDenied 包住一次询问。PreCompact 和 PostCompact 包住上下文压缩。SubagentStart 和 SubagentStop 包住已经派发的子 Agent。AgentSpawn 在派发之前运行，可以拒绝这次派发，或改掉 Agent、模型、目录和后台标志。

还可以使用 InstructionsLoaded、ConfigChange、Notification、FileChanged、CwdChanged 和 DirectoryAdded。--safe-mode 会跳过设置里的 hooks。--bare 也会跳过。托管策略可以把 hooks 限制为托管集合。
