# 图像 API

通过独立于 Chat 的服务生成、编辑图像并查询原生图像任务。

<a id="generate"></a>

## 生成图像

client.images() 与 Chat 共享配置和传输，但具有独立的请求、模型目录、凭据选项、能力与路由。chat().models() 不包含图像输出模型。

### 图像函数 · 从异步宿主调用

```rust
use lingxi_llm_client::{builtin_providers, LlmClientBuilder};
use lingxi_llm_client::protocol::{
    ImageGenerationRequest, ImageOutputOptions, ImageRequestOptions, Region, Secret,
};

async fn generate(api_key: String) -> Result<(), Box<dyn std::error::Error>> {
    let profiles = builtin_providers()?.into_iter()
        .filter(|profile| profile.profile_name == "openai").collect::<Vec<_>>();
    let client = LlmClientBuilder::new(&profiles)?
        .with_region(Region::International).build()?;
    let request = ImageGenerationRequest {
        model: "gpt-image-1.5".into(),
        prompt: "An orange cat on a blue background".into(),
        references: vec![],
        output: ImageOutputOptions::default(),
        provider_options: Default::default(),
    };
    let options = ImageRequestOptions {
        credential: Some(Secret::new(api_key)),
        ..Default::default()
    };
    let result = client.images().generate_in("openai", &request, &options).await?;
    println!("{} images", result.images.len());
    Ok(())
}
```

验证方式: 编译检查 (llm-image-generation)

<a id="image-workflow-choice"></a>

## 选择即时结果或持久任务

1. 先为精确连接/模型调用 capabilities_in，再填写受支持的尺寸、参考图、遮罩与任务选项。
2. 提交后存储返回引用，并按宿主设定间隔查询。account_scope 与凭据始终绑定同一账户。
3. 提交结果未知时应核对现有状态，不能仅因首个响应丢失就新建图像任务。

| 路径 | 何时使用 | 需要保存 |
| --- | --- | --- |
| generate_in / edit_in | 配置路由直接返回完成图像 | 输出来源、请求 ID、执行连接与用量，并及时保存临时媒体 |
| submit_in → get_task | 所选供应商提供原生异步任务 | 离开页面或重启进程前保存精确 ImageTaskRef |

<a id="image-error-actions"></a>

## 避免重复生成的错误恢复

| ImageError::dispatch() | 已经确定的事实 | 宿主动作 |
| --- | --- | --- |
| NotSent | 该图像操作未发送生成请求 | 修正本地输入、能力或作用域后重新准入 |
| Rejected | 供应商拒绝操作 | 根据底层类型化错误修正请求或账户 |
| Unknown | 请求可能已被接受 | 保留本次调用元数据，核对后再考虑重新提交 |
| Accepted | 即使结果处理失败，仍已确认供应商接受 | 尽可能恢复现有结果或任务 |

<a id="inputs"></a>

## 参考图、遮罩与输出

- 支持的输入包括 HTTP(S) URL、带媒体类型的 Base64，以及应用拥有的 AttachmentRef。附件引用需要在 builder 中配置 AttachmentResolver。
- ImageGenerationRequest.references 在受支持的模型上添加参考图。MiniMax 角色参考图使用 ImageReferenceKind::Character。
- 遮罩需要模型明确支持。OpenAI 遮罩仅用于 image_index = 0；其他索引在发送前失败。
- ImageResponse 保留原始 URL 或 Base64、执行连接、请求 ID、结果状态与可用用量。应用应及时保存临时 URL 的内容。

<a id="image-providers"></a>

## 供应商覆盖

- OpenAI：生成、编辑与遮罩。Gemini：生成、参考图与编辑。
- Qwen 区域连接：生成、参考图、编辑与原生任务，具体模型由区域账户决定。自定义 Wan 路由需显式配置工作空间端点。
- xAI：生成与编辑。MiniMax：生成与角色参考图。GLM/Z.AI：生成与原生任务。
- OpenRouter：生成、参考图与编辑取决于上游模型和端点。仅支持兼容 Chat 协议不代表支持图像路由。

图像调用不会自动重试、切换连接、轮询或持久化任务。超时后供应商仍可能继续生成。图像用量独立于 Chat token 成本估算；目标账户能力需要验证。

<a id="image-lifecycle"></a>

## 图像发送、持久化与失败

capabilities_in 在解析图像附件或发送前校验精确连接/模型。Generate/edit 返回 ImageResponse；submit/get_task 仅用于受支持原生任务路由。图像任务引用保留原连接、端点、模型与账户；宿主持久化并按供应商支持选择轮询/取消。

应用处理前保留原生 URL/Base64 与输出元数据。供应商超时后生成可能仍在运行；响应丢失不能静默转为另一次图像请求。ImageError dispatch 区分未发送、拒绝、已接受与未知结果，供宿主恢复。不能假设图像生成适用 Chat token 价格。

- 应用 AttachmentRef 输入要求已授权 resolver；供应商图像 URL 输入仍由供应商管理。宿主应保留已有透明度/遮罩语义，不能编造不支持的选项。
- images 测试使用模拟响应证明能力准入、编码与类型化任务行为。真实账户模型权限、输出质量、临时 URL 过期与目标设备显示需单独验收。
