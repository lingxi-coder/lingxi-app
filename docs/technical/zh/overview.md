# SDK 与开发者工具

用灵犀构建你的应用。从模型调用、Agent 编排，到移动端 Linux 运行时，选择适合你的 SDK，开始创造。

<a id="choose-sdk"></a>

## 选择你的起点

每个 SDK 负责一层清晰的能力：LLM Client 连接模型，Harness Runtime 管理 Agent 执行，Mobile Linux 为 Android 和 iOS 提供本地运行环境。你可以独立使用，也可以组合集成。

- [Harness Runtime](harness.md)
- [LLM Client](llm-client.md)
- [Mobile Linux](mobile-linux.md)
- [产品 Bridge](bridge-client.md)

<a id="sdk-map"></a>

## 能力一览

三个独立 SDK 仓库，以及产品仓库中的 TypeScript Bridge 和原生宿主集成。API 索引为与提交一致的文件提供精确版本链接，并将修改文件标记为工作树源码。

| SDK / 集成 | 职责 | 入口 |
| --- | --- | --- |
| Harness Runtime | Agent 循环、会话、工具、权限与生命周期 | Rust 门面；desktop/mobile/headless |
| LLM Client | 模型协议、传输、流与 Provider 服务 | Rust LingxiClient |
| Mobile Linux | 本地执行、PTY 与验证资源 | Rust 契约、Kotlin/Swift 门面 |
| 产品 Bridge | 产品宿主传输与客户端 DTO | 内部 Node.js 客户端与原生 FFI |

<a id="integration"></a>

## 开始集成

- 调用模型：使用 LLM Client，配置你自己的模型服务商凭据。
- 运行 Agent：为 Harness Runtime 提供会话运行时与宿主生命周期。
- 在移动端执行：使用 Rust API，或接入 Android／iOS 的原生封装。
- 集成灵犀产品：在产品构建中接入内部 Bridge 与平台封装。

<a id="source"></a>

## 源码与版本

示例依据当前仓库整理。Git 依赖应固定到经确认的提交；各平台页说明原生安装方式与运行条件。接口摘录与源码声明索引一起帮助你定位实现。

Bridge 是产品内部的 Node.js 包。Rust SDK 与 Python／npm SDK 不同；CLI 安装包安装的是应用，而非这些库。
