# 设置文件

用户设置在配置目录里。项目设置在仓库里。并不是每个键都按同一种方式合并。

<a id="files"></a>

## 这些文件

LINGXI_CONFIG_DIR 未设置时，配置目录是 ~/.lingxi，全局文件是 ~/.lingxi.json。设成非空路径时，会话设置从那个目录读取。空值对命令行来说仍然算已设置：它是相对路径，所以命令行会从你启动灵犀的目录来解析。/doctor 打印它正在使用的配置目录。查找 ~/.lingxi.json 时，空的 LINGXI_CONFIG_DIR 视为未设置。

| 文件 | 用途 |
| --- | --- |
| ~/.lingxi/settings.json | 你的设置，包括 model 和 permissions.defaultMode。 |
| .lingxi/settings.json | 可以提交到仓库的项目设置。 |
| .lingxi/settings.local.json | 项目本地设置。Git 会忽略这个文件。下面的权限模式读取器不会加载它。 |
| ~/.lingxi.json | 另一份全局文件。它不是 settings.json。 |

<a id="permission-mode"></a>

## 权限模式如何决定

决定权限模式时，命令行先读用户的 settings.json，再读项目的 .lingxi/settings.json。permissions.defaultMode 以项目里的值为准。任一文件关闭了 bypass 或 auto，这个关闭就会保留。只有用户文件可以授予 auto 或 bypassPermissions。项目文件里写下这两种模式并不会授予它们。

--settings FILE_OR_JSON 在这些文件之后生效，加上 --restricted 时也仍然生效。--setting-sources user,project,local 选择这个读取器要打开哪些环境中的文件。不写这个参数时，它读取 user 和 project。--restricted 两者都不读。这个读取器不会打开 settings.local.json。其他键，包括 hooks，有各自的文件，并不按这同一条规则合并。

### 在用户设置里使用计划模式

```json
{
  "permissions": { "defaultMode": "plan" }
}
```
