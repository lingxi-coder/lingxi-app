# 诊断、排障与运行恢复

将故障定位到责任层，恢复会话与运行资源，并收集不泄露凭据的有效证据。

<a id="triage"></a>

## 定位故障责任方

| 现象 | 优先检查 | 恢复边界 |
| --- | --- | --- |
| 客户端连接失败 | Bridge 进程、发现/握手与 SDK 版本 | 传输连接建立前不要推定模型故障 |
| 模型请求被拒绝 | 实际连接/profile、能力、认证与类型化错误 | 由宿主处理刷新/重试，保留 attempt 元数据 |
| 工具持续等待 | 权限/交互请求责任方、取消与任务 ID | 恢复或取消原请求，避免重复执行 |
| 原生 guest 执行不可用 | 平台/后端、资源完整性与显式运行策略 | 修复声明资源，模拟器不会变成设备后端 |
| 文档新鲜度失败 | 引用源码改动与产品固定版本 | 审查正文后重新生成，勿手改生成产物 |

<a id="sessions"></a>

## 会话与关闭恢复

关闭前停止接收新工作；取消或等待已有回合，并在持久化写入结束前保留运行时 owner。ShutdownReport.complete 决定清理是否完成。恢复应依据持久化身份和结构化历史，不能匹配显示文本。

- [生命周期与关闭](harness-lifecycle.md)
- [会话与恢复](harness-sessions.md)

<a id="resources"></a>

## 执行资源与绑定

修复前按声明的清单/校验和与目标 ABI 检查 rootfs/原生资源。DTO 或签名版本不匹配时重建原生绑定。保留无关用户会话和凭据，源码重建不构成删除它们的理由。

- [资源策略与授权](mobile-authorization.md)

<a id="evidence"></a>

## 有效诊断证据

- 记录仓库/SDK 固定版本、平台、feature、会话/请求身份及最终结果。
- 保留类型化错误类别与脱敏 attempt 元数据。报告中不得粘贴 Provider key、凭据文件、签名账户 token 或本地机密。
- 描述实际运行的检查及证据截止范围。界面超时、沙箱限制或模拟器限制需要精确复现边界。

<a id="verify"></a>

## 恢复后的核对

1. 确认启用的是预期源码与运行时身份。
2. 运行最相关的传输、生命周期、模型或资源检查。
3. 核对受影响会话的持久化与正常结束。
4. 单独记录剩余真实 Provider 或设备验收。
