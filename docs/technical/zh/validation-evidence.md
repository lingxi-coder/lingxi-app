# 验证方法与证据边界

理解文档检查、消费者编译、模拟测试、真实 Provider 调用与设备验收分别能证明什么。

<a id="levels"></a>

## 证据层级

| 检查 | 证明 | 仍需单独验收 |
| --- | --- | --- |
| 内容、类型、导出检查 | 双语覆盖、路由、锚点、确定性产物与渲染器契约 | 每个运行时能力的真实性 |
| 编译器消费者示例 | 声明依赖及公共类型、方法可用性 | 模型凭据、Provider 响应及设备后端 |
| 模拟运行时测试 | 无需真实服务的特定生命周期、错误与取消契约 | 原生输入、真实服务及生产行为 |
| 真实服务、设备、包内测试 | 所测试目标、身份与场景 | 未测试平台、模型、完整对齐及全面发行就绪 |

<a id="docs"></a>

## 手册与源码新鲜度

docs:check 检查引用的工作树源码、API 目录与两种语言导出。docs:check:content 使用保存的内容/基线进行检查，不要求相邻 SDK checkout，适用于文档 CI。检查命令不重写被跟踪文件。

### 确定性来源与内容检查

```sh
cd lingxi-app/apps/web
npm run docs:sync
npm run docs:check
npm run docs:check:content
npm run docs:examples -- --workspace ../../..
```

<a id="consumers"></a>

## 验证实际复制的消费者

示例验证器提取手册中标记的 Rust 代码块，使用完整清单测试所支持的独立示例，并检查 SDK 来源身份。隔离的本地 overlay 显式声明。固定 Git 安装示例另按固定提交验证；使用较新的本地 SDK 编译不能证明该 Git revision 可用。

compile 与 mock 标签描述验证方法，不表示所有环境都已通过。实际通过、失败与先决条件以验证器报告为准。

<a id="parity"></a>

## 对齐与带日期报告

原生兼容报告对应具体版本、分发物、设置和 fixture。字节级协议结论需要原生与运行时原始产物对比。旧设计里程碑、累计测试数量和官网构建通过，不能证明当前平台或完整对齐验收。

<a id="report"></a>

## 记录验证结果

1. 记录源码 revision、未提交输入指纹、目标与 feature 组合。
2. 分别记录编译、模拟执行、服务调用、打包与设备证据。
3. 保留失败和环境前提，不把工具缺失记为通过。
4. 后续源码改变时重新执行受影响的定向检查。
