# 桌面端 `lingxi-api` 自动调用验收

2026-11-18 在 Apple Silicon macOS 27.2 上测试签名安装版 LingXi Code `0.1.0`。产品源码为 `a7dcd5f6d920f64a924eb8763cce5eaa58a6978d`，Harness 为 `f50814ec8381f10756f66eadf457474d90bcc69a`。

## 默认模型

| 输入 | Chat · `gpt-6-luna` | Code · `gpt-6.1-sol` |
| --- | --- | --- |
| 在灵犀里怎么创建一个团队？请说明操作步骤。 | 命中 | 命中 |
| 如何配置团队里的 Bot 自主回复，让它在没有被 @ 的时候也能自己判断要不要回答？ | 未调用 | 命中 |
| 如何把我做的 Local App 共享给一位同事？ | 未调用 | 命中 |

每次通过桌面输入框在全新、无项目的会话中发送一条自然语言问题。所有会话的初始技能列表都包含 `lingxi-api`。命中依据为会话转录中实际调用 `Skill`、工具成功返回并记录 `lingxi-api` 激活。

默认 Chat 的 Bot 回答在表示要确认配置后结束。Local App 回答给出了不存在的应用内选择同事并发送入口。Code 的 Bot 回答覆盖了维护者的 Decision 服务、Bot 发布设置与目标会话的开关。Local App 回答说明了私下传递源码 ZIP 的流程。

## 同模型对照

在两个新 Chat 会话中选择与 Code 相同的 `gpt-6.1-sol`，逐字重问 Bot 和 Local App 两题，两题均自动调用 `lingxi-api`。默认模型下 Chat 命中 1/3，Code 命中 3/3。同模型对照仅覆盖默认 Chat 漏掉的两题。

## 安装与启动

首次隔离验收在创建 Electron 钥匙串加密项时超时。同一签名包随后在已登录用户的图形会话中通过官方冷启动、凭据持久化和重启恢复验证。安装版完成真实模型测试后，以常规方式重启并显示主窗口，用户凭据服务正常运行。

## Chat 自动调用修复后复测

在产品基线 `f3f37966820c0749c3b4a97d17a696f8bfe21708` 上固定 Harness `d6ef4dd1b52f9ed48d6427e1238c35a850de70f6`，重新构建、签名和安装。签名包通过官方静态检查及隔离冷启动验收。

从上次使用 `gpt-6-luna` 的 Chat 恢复会话，再通过新建按钮让六个空会话继承原模型。逐字发送原问题，每轮只有一条人工消息。模型在 Bot 自主回复和共享 Local App 两题上各两次自动调用 `lingxi-api`，分别加载 `teams#auto-reply` 和 `local-apps#source-zip`。创建团队也自动命中。无关的蓝天成因问题直接回答，工具调用数为零。
