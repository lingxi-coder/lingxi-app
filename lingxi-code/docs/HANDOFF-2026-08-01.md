## 6. 接手前必须知道的坑

这些是反复付出过真实代价换来的，按"最容易再犯"排序。

1. **在 oracle 上核实，不要推断。** oracle 是
   `~/.local/share/claude/versions/2.1.220` 的**真实二进制**；`claude-code/src` 是旧的。
   枚举值要读出来，不能猜。
2. **🚨 在二进制里 grep `·` 永远返回 0** —— 二进制存的是 JS 转义 `\xB7` 而不是编码后的字符。
   带中点的文案必须按**转义形式**验证，否则会把存在的字符串报成缺失。
   （在 Rust 侧 grep `·` 是正常的。）
3. **给任何新 grep 配一个"已知不存在"的对照串。** 二进制同时含 UTF-8 与 UTF-16LE，
   没有对照串的模式匹配会产生假阳性。
4. **大约一半的真实缺陷是"命名了、算出来了、但从来没接线"。** 相信一个功能存在之前，
   先 grep 它的发布点/调用点。
5. **"被封锁"往往是没把谓词抽出来。** 本轮 7 个自称 blocker 里 7 个都不成立
   （provider 路由信号其实读 ENV、HTTP status 其实在 message 里、API-key 来源其实已有
   `AuthSource`、synthetic tool result 其实已经做完了……）。
   **这个端口说某事被封锁时，先 grep 再信。**
6. **存活下来的 mutation 可能根本没应用上。** 断言替换次数（`assert s.count(pat)==1`）
   再相信结果 —— 一个静默不匹配的 `perl -0pi` 和一个健壮实现长得一模一样。
7. **合并前 `cargo build --workspace`**（`--tests` 会跳过 doctest；单 crate 测试会漏掉
   跨 crate 的 match 破坏）。
8. **不要在同一个 checkout 里并行跑编辑 agent**，会互相覆盖；worktree 隔离时
   shell 的 cwd 会静默回到主仓，永远用 `git -C <worktree>`。
9. **`git checkout -- <file>` 会丢掉该文件里全部未提交改动**，做 mutation 测试请用 `cp` 备份。
10. **`git log -- session/` 查不到东西**是因为仓库内路径带 `lingxi-code/` 前缀 ——
    仓库根在它上面一层。
11. **目录名/前缀是有意改过的**：`.lingxi`、`LINGXI_`、`LingXi` 是刻意的品牌重命名，

## 9. 2026-08-01 追加：`Login expired` 已完成

第 5.1 节原本把它列为"没有落点"。**那个判断是错的**，而且错得很典型 ——
正是本文第 6 节第 5 条描述的那种错误。

### 落点一直都在

`llm-client/src/oauth/anthropic/credential_provider.rs` 里：

```rust
.map_err(|_| LlmError::Authentication)?   // ← 把三种刷新失败塌缩成一种
```

刷新失败**确实**会到达请求路径，只是**原因被丢掉了**。所以缺的不是"面"，
是"事实透传" —— 和本轮 HTTP status 那件事是同一个形状。

### oracle 事实（2.1.220，逐条在二进制里核实过，配了对照串）

- `se_ = "Login expired \xB7 Please run /login"`（@230618923）
- 渲染点：`if(e instanceof qQt) return yu({error:"authentication_failed",
  content:_n() ? "Failed to authenticate: OAuth session expired and could not be
  refreshed" : se_})`
- `qQt = class extends Error { name = "OAuthRefreshDeadError" }`，构造消息是
  "OAuth refresh token is no longer valid; run /login to re-authenticate"

关键：oracle 用的是**独立的错误类**，不是消息匹配。所以端口也用独立的
`LlmError` 变体，而不是去嗅探文本。

### 落地

| 文件 | 改动 |
|---|---|
| `llm-client/src/error.rs` | 新增 `LlmError::OAuthRefreshDead` 变体 |
| `credential_provider.rs` | 新增 `llm_error_for()`：**只有** `RefreshFailed`（IdP 拒绝了 refresh token）算 dead session；`TokenStale`（别人先轮换了）和 `ProviderUnreachable`（网络）仍是 `Authentication` |
| `api_error_copy.rs` | `oauth_refresh_dead_text(interactive)` + `AUTH_COMMAND` |
| `conversation.rs` | `model_error_text` 新增渲染臂；`classify_api_error` 记 `authentication_failed` 且 **不写 status** |
| `retry.rs` / `model/retry.rs` | 归入**终止**类：refresh token 被拒，重试再多次也不会变有效 |
| `service.rs` | `error_kind` → `"unauthorized"`；`status_of` → **`None`** |

**这不只是补一句文案，是修了一个真 bug**：改之前，IdP 暂时不可达（网络问题）
和 refresh token 被永久拒绝，对用户显示的是**同一句无用的话**。

### 两个刻意的"不"

- **不伪造 HTTP status。** 刷新是本地对 IdP 发起的，模型 API 根本没被请求过，
  所以 `status_of` 和 `classify_api_error` 都给 `None`。
  编一个 401 写进 transcript，正是本轮 status 溯源工作要消灭的那种谎。
- **不动 `OAuthError::RefreshExpired` 的 `Display`。** 它是 LingXi 特有的
  （`OAUTHREF.5`）且是 `refresh.rs` 的控制流 key。

### 验证

TDD 全程：两个测试都**先看着它因为符号不存在而失败**，再实现。
另外补了渲染层的接线测试（`a_dead_oauth_session_renders_the_login_expired_copy`）
和一条反向保险（`an_ordinary_auth_failure_is_not_reported_as_an_expired_login`）。

**两次变异测试都被杀死**（都断言了替换次数，避免"静默没替换"冒充"变异存活"）：

1. 删掉渲染臂 → 接线测试失败，落回 `Display` 的 **"oauth session expired"** ——
   正是这件事要消灭的裸 Display 泄漏。
2. 把 `RefreshFailed` 映射改回 `Authentication` → 映射测试失败。

> 接线测试是必需的：文案常量的单元测试**无法**发现一个永远不会被走到的 match 臂。
> 本项目约一半的真实缺陷是"命名了、算出来了、但从来没接线"。

## 12. 2026-08-01 追加：两条「偶发」失败其实是测试隔离缺陷

修完第 11 节那 6 条后，全量跑又冒出两条：

- `agent::f_description_l_gate_tests::background_bullet_carries_the_full_long_arm`
- `token_warning_banner::tests::above_error_threshold_colors_context_low_as_error`

两条**单独重跑都稳过**。但**「单独跑能过」同时符合两种解释**：机器负载导致的
flaky，和**测试之间通过进程全局互相污染**。看断言内容才能分辨 —— 这两条的
失败输出都是「拿到了另一种配置下的正确结果」，是后者。

### 12.1 一条锁只保护「拿了这把锁的人」

| crate | 进程全局 | 谁在改 | 谁在读却没拿锁 |
|---|---|---|---|
| `compaction` | `DISABLE_COMPACT` | `thresholds::tests`（持 `ENV_LOCK`） | `token_warning_banner::tests` |
| `tools/agent` | `LINGXI_FORK_SUBAGENT` | `agent_test.rs` 的 fork 测试（持 `AGENT_LIST_ENV_LOCK`） | `agent.rs` 的 `f_description_l_gate_tests` |

两处的锁都**定义在别的模块的 test mod 里**，读侧**够不着**。
`compaction` 已把 `ENV_LOCK` 提到 crate 级；`tools/agent` 已把
`AGENT_LIST_ENV_LOCK` 提到 `agent.rs` 模块级，读侧加了

> 成立（它是显式传参），但 **builder 内部还会读 `LINGXI_FORK_SUBAGENT`** ——
> 注释是对的那一半掩盖了错的那一半。已改正。

### 12.2 🚨 更狠的一条：**两把锁守同一个全局 = 没有锁**

上面改完，`tools/agent` 8 次里还挂 1 次，但换成了另一条测试
`build_prompt_pro_plan_gate`。失败断言是 **background bullet**，
它由 `LINGXI_DISABLE_BACKGROUND_TASKS` 决定 —— 而：

- 后台测试改这个变量时持 **`BG_DISABLE_ENV_LOCK`**
- 提示词测试读这个变量时持 **`AGENT_LIST_ENV_LOCK`**

**两把不同的锁，守同一个进程全局，谁也挡不住谁。** 已合并为一把。
合并后 `tools/agent` 连跑 8 次全绿，`compaction` 连跑 6 次全绿。

> 🚨 **判据：锁的作用域应该由「被保护的状态」决定，而不是由「哪个测试先需要它」。**
> 看到同一个 env / 全局出现在两个锁下面，就等于没锁。

### 12.3 🔴 `bg_attach`：一条被 `unwrap()` 掩盖了的真实竞态

`attach_socket_reports_error_and_exit_frames` 也是「单独跑必过、全量跑偶挂」。
第一反应是调度延迟，于是把 `read_frame(...).unwrap()` 换成重试到 30s 的
`read_frame_waiting`。**结果失败反而变成了整整 30 秒才挂** ——
这直接证伪了「延迟」假设：帧**根本不会来**。

产品侧顺序（`apps/cli/src/bg_attach.rs`，client 接入路径）：

```rust
write_frame(&mut stream, FRAME_READY, ...)?;   // ← 先告诉客户端「你连上了」
...
hub.activate_controller(id, ...)               // ← 这里才注册进广播表
```

**客户端拿到 `FRAME_READY` 之后、`activate_controller` 之前，
hub 广播的任何帧都会丢。** 测试正好在这个窗口里 `hub.error("failed")`。

这不只是测试问题：生产里同一个窗口会**丢掉一段终端输出**。

⚠️ **没有直接调换顺序**，因为那会引入另一个方向的错误：先 activate 再写 READY，
中间的输出帧就会排在 READY **前面**，而客户端（含 `connect_client`）假定
第一帧必须是 READY。正确的产品修法是「先注册、但把出站帧缓冲到 READY 写完」，
那是一次有设计取舍的改动，**留给产品裁定**。

本次只让测试确定：新增 `#[cfg(test)] controller_is_active()`
（`has_clients()` 分不出 `Reserved` 和 `Active`，所以不能用），测试先等 Active 再广播。
改后连跑 8 次全绿且耗时正常（不再出现 30s 等待）。

> 🚨 **方法论：一个「重试更久」的修法如果让失败耗时变长而结果不变，
> 那就是把「慢」的假设证伪了 —— 剩下的解释是「丢了」。**
> 这条竞态之所以能长期潜伏，正是因为原来的 `unwrap()` 把它伪装成 2 秒超时抖动。

### 12.4 `engine-mobile` skeleton：等错了东西

`submit_send_prompt_drives_listener_text_then_turn_ended` 和
`completed_mobile_turns_are_persisted_and_listed_per_session` 都会偶发挂在
**`cannot start a new session while a turn is in flight`**。

第 4.1 节曾把前者归因为「机器满载」。**那个归因是不完整的** ——
真正的原因和 12.3 的 `bg_attach` 是同一形状：**事件先到，状态后清**。

- 测试自旋等的是监听器上的 `TurnEnded` 事件；
- `NewSession` 的门却是 `host.rs:3183` 的 `self.active_cancel`，
  它在 turn 任务**收尾时**才被丢弃 —— **严格晚于**终结事件发出。

所以「等到 `TurnEnded`」根本不是这些测试需要的前置条件，两者之间永远有一个窗口；
机器一忙，窗口就变宽。原来的 `for _ in 0..2000 { sleep(1ms) }`（约 2 秒）
**还会静默放弃**：超时后不报错，继续往下走，于是失败以一句
不知所云的 `Rejected` 出现在后面几行。

已改成 `start_new_session()` 帮助函数：**直接对真正的前置条件重试**
（提交 `NewSession`，遇到 mid-turn 拒绝就退避重试，30s 上限后**断言失败并打印真实错误**），
而不是猜一个时长。改后连跑 6 次全绿，且耗时正常。

> 🚨 **通用判据：自旋等待要等「你真正依赖的那个状态」，不是等一个碰巧相关的事件。**
> 有界自旋如果超时后不断言，就是把一次确定性失败换成了后面某处的离奇报错。

```rust
LlmError::Authentication | LlmError::PermissionDenied
    if is_oauth_revoked(err.http_status(), &err.to_string()) => ...
```

`err.to_string()` 对这两个变体永远是固定的 `"authentication failed"` /
`"permission denied"`，`http_status()` 也因为没有前缀而永远是 `None`。

⇒ **`is_oauth_revoked` / `is_api_key_auth_disabled` / `mentions_api_key_header`
以及新加的 `is_oauth_org_not_allowed` 全部永远为 false。**
用户拿到的一直是裸 `Display`：`permission denied`。

之前 memory 里记的「auth 家族 9 取 7 已 landed」是**只写到了一半** ——
文案常量存在、有逐字节测试，但**没有一条能到达用户**。
这正是本项目最常见的缺陷形态：**命名了、算出来了、但从来没接线**。

### 13.2 修法

给两个变体加上 `message: String`（**`Display` 保持不变**，所以所有渲染/匹配
既有行为不受影响），并新增：

```rust
pub fn provider_message(&self) -> Option<&str>   // 变体保留下来的 provider 原文
pub fn http_status(&self)                        // 改为基于 provider_message 解析
```

四个门改成读 `err.provider_message()` 而不是 `err.to_string()`。
解码器（anthropic / gemini / openai / `map_error_status`）现在把
`display`（带 SDK 状态前缀的原文）**存进变体**。

⛔ 注意这和「**不要给 `LlmError` 加 `status` 字段**」不矛盾：
那条是因为 status 会波及约 250 个构造点，而这里是 82 处引用 / 约 55 个构造点，
且**机制上必须**如此 —— oracle 的门本来就匹配报文内容。

### 13.3 顺带补上的一条真实缺失分支

`de_()` → `ce_`（oracle @230619663，401/403 且报文含
`OAuth authentication is currently not allowed for this organization`）：

> Your organization has disabled Claude subscription access for **LingXi** ·
> Use an Anthropic API key instead, or ask your admin to enable access

端口此前**零命中**。它和 `ORG_DISABLED_PREFIX` 是**镜像关系**：
一个说「订阅通道被关了，去用 API key」，另一个说「API key 被关了，去登录」。
**顺序弄反会把用户指向他们组织刚刚关掉的那条路**，所以渲染臂严格按 oracle 的
先后放置。

### 13.4 gateway 分支（`Epo`）—— 现状裁定

oracle 的门是：

```js
if (e instanceof Error && e.message.toLowerCase().includes("x-api-key")) {
  if (qOu()) return UOu;                    // remote/transient   ← 已移植
  if (xn()==="gateway") return Epo;         // ← 本项
  let {source:i} = e1(); ...                // credential rejection ← 已移植
}
```

而 `xn()` 的完整定义（@227682549）是：

```js
function xn(){ if(C_()) return "gateway"; return Z.CLAUDE_CODE_USE_BEDROCK?... }
```

⚠️ **`if(C_()) return "gateway"` 是第一顺位，压过所有环境变量** ——
`ErrorRouteTag::from_env()` 的文档只写了 `USE_BEDROCK` 压 `USE_VERTEX`，
**漏了这一层**，接手时请注意。

`C_()` = `Mt.gatewayAuth`，是一个**运行时凭据对象**（`U5e()` 写入、
`CTi()` 判过期、`$5e()` 判 unpinned）。端口**没有任何 gateway-auth 状态**，
所以这条分支即使移植也永远取不到 —— 属于「先做功能，再谈文案」。
**仍需产品裁定 gateway-auth 是否在范围内。**

### 13.5 终结臂（terminal 401/403 arm）已补 + `sir()` 仍缺

13.1 的修复让所有 auth 分支变得可达之后，暴露出**最后一条也没移植**：

```js
// @230607344 — 上面每条具体分支都不匹配时
return yu({error:"authentication_failed", content: _n()
  ? `Failed to authenticate. ${IT}: ${i}`
  : `Please run /login \xB7 ${IT}: ${i}`})
```

端口此前直接落到变体的裸 `Display`（`permission denied`）。
现已补上 `auth_failed_fallback(interactive, detail)`。

⚠️ **`i` 是 `sir(e)`（@230583592），这个函数整体没有移植**（端口 0 命中）。
常见路径上 `sir(e)` 就是 `e.message`，也就是
`LlmError::provider_message()`，所以**常见路径是逐字节正确的**；
但它的特例分支全部缺失：

| `sir` 分支 | 文案 |
|---|---|
| `StreamSuspended` | `Connection interrupted by system sleep` |
| `ETIMEDOUT` | `Request timed out. Check your internet connection and proxy settings` |
| 7 个 SSL code 分支 | `Unable to connect to API: …` |
| `e.message==="Connection error."` | `Unable to connect to API (code)` / `… Check your internet connection` |
| 空 message | `FOu(e) ?? "API error (status …)"` |

⛔ **不要拿端口的 `llm_client::ssl::ssl_hint` 冒充这些** ——
那是 oracle 的**另一个**函数（`YLe`），文案完全不同。
`sir()` 应作为一个独立单元移植，它同时被错误面的多处使用。
