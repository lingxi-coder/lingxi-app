## slab 0.4.6 → 0.4.12 — hold delta for panic-state defect

Source ID `registry+https://github.com/rust-lang/crates.io-index#slab@0.4.12`, base checksum `eb703cfe953bccee95685111adeedb76fabe4e97549a58d16f03ea7b9367bb32`, target checksum `0c790de23124f9ab44544d7ac05d60440adc586479ce501c1d6d7da3cd8c9cf5`. Read both manifests, full directed archive diff, the added `src/builder.rs`, modified `src/lib.rs` and `src/serde.rs`, and target tests. Added files are `Cargo.lock`, `SECURITY.md`, and `src/builder.rs`; no files removed. Neither packaged archive contains a root Cargo build script (the target also explicitly sets `build = false`). The package-local lock is not the App lock. The `serde` feature is optional; the earlier graph snapshot had `default,std`, not `serde`.

The builder moves sorted/unsorted pair construction and free-list repair into a separate module. A large caller-supplied key causes it to fill vacant slots and may exhaust resources; serde and caller input limits must be considered separately. New safe `get_disjoint_mut` rejects duplicate keys before raw-pointer operations, checks each key against the entries length, rejects vacant slots, and initializes each output before `assume_init`; `Entry<T>` is non-zero-sized due to its `Vacant(usize)` variant. These observations are not a formal proof of every aliasing property, and existing unchecked accessors still impose caller obligations.

The new custom `Slab::clone_from` (target `src/lib.rs:167-170`) first calls `self.entries.clone_from(&source.entries)` and copies `len` and `next` only afterward. If cloning a contained value panics and unwinding is caught, entries can be partially changed with old metadata. The independently compiled `slab-clone-check/main.rs` fixture uses both archive-matched sources directly and rustc 1.94.0: in debug mode the baseline remains `len=2, present=2`, with iteration/insertion succeeding; target is `len=2, present=3`, with iteration and insertion both panicking. With `-C opt-level=3 -C debug-assertions=no`, the same baseline stays consistent, while target remains `len=2, present=3` and insertion panics; iteration completes for this input. Direct rustc 1.98.1 runs produced the same respective observed outcomes and are supplementary, not workspace-toolchain evidence. The older lane B probe also exercises bounded disjoint-key and builder cases, but this cross-review did not rerun that probe.

This is a reproducible package-level availability and post-unwind invariant defect, not a demonstrated memory-safety violation, product exploit, or established attacker-reachable path. A search of the five direct dependency sources in the earlier graph found real Slab uses and no literal `.clone_from(` calls, which is not proof against indirect calls, derived cloning, or other consumers. Until consumer/panic reachability or remediation is resolved, do not support the proposed `safe-to-deploy` delta; `safe-to-run` was not separately proposed or independently decided. The existing baseline also requires a valid locked import; neither this hold nor a source hash is a replacement for that chain.
