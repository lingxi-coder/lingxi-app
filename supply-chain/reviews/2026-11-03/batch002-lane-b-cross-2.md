## cfg_aliases 0.1.1 — support full proposal with environment limitations

ID `registry+https://github.com/rust-lang/crates.io-index#cfg_aliases@0.1.1`; archive SHA-256 `fd16c4719339c4530435d38e511904438d07cce7950afa3718a84ac36c10e89e`. Read complete `src/lib.rs` and both manifests; no other Rust files or build script are packaged. This is a build-script helper: the exported macro parses caller-provided alias tokens, recursively expands aliases, uses `CARGO_CFG_*`/`CARGO_FEATURE_*` environment variables, and emits `cargo:rustc-cfg` for true aliases (175–371). Boolean list parser expands to `&&`/`||`, and alias output is an identifier, rather than arbitrary environment text in Cargo directives. The version tests the presence of a `CARGO_CFG_` variable, and value comparisons fall back to an empty string when missing; incorrect or absent build environment can misconfigure the resulting alias, especially comparison with an empty expected value. Cyclic/malformed expressions may fail compilation. `CARGO_CFG_DEBUG_ASSERTIONS` availability depends on Cargo environment/version; this version has no PROFILE fallback. The crate has no crate-local unsafe, network, file, or subprocess behavior. Inputs/build environment and the gated product code remain separate. Given documented trusted build-script inputs, support full `safe-to-deploy` (including `safe-to-run`) with these limitations in notes. No tests were run.

## cfg_aliases 0.2.1 — hold: actual false debug alias

ID `registry+https://github.com/rust-lang/crates.io-index#cfg_aliases@0.2.1`; archive SHA-256 `613afe47fcd5fac7ccf1db93babcb082c5994d996f20b8b159f2ad1658eb5724`. Read complete `src/lib.rs`, both manifests, and its packaged integration test. Relative to 0.1.1, the helper emits `cargo:rustc-check-cfg` and guesses `PROFILE=debug` if the actual `CARGO_CFG_DEBUG_ASSERTIONS` is absent (`src/lib.rs:177–189`). A valid dev profile can disable debug assertions; absence then means false, but this fallback returns true. This changes compiler cfg selection, potentially including code that a caller expected to exclude.

Actual Cargo/rustc 1.94 test: `cfg-aliases-probe/` uses the archive-matched current package via path dependency, defines `[profile.dev] debug-assertions=false`, and emits `alias_debug: { debug_assertions }`. `cargo run --offline` produced `PROFILE=Ok("debug")`, `CARGO_CFG_DEBUG_ASSERTIONS=Err(NotPresent)`, `alias_debug=true`, `builtin_debug_assertions=false`; the fixture asserted the mismatch. As a control, `[profile.release] debug-assertions=true` had `CARGO_CFG_DEBUG_ASSERTIONS=Ok("")`, and both flags were true. The intentionally mismatch-asserting control exited 101, as expected, demonstrating that the two outputs need not disagree. All this is local and does not establish attacker control or a product vulnerability. The other lane observed no debug_assertions alias in its bounded current direct-caller scan. Nevertheless, because a documented configuration expression may compile a different branch from the builtin on a reasonable profile, hold the unconditional full deploy proposal pending independent judgment or upstream/consumer repair; no `safe-to-run`-only record is offered as a replacement for the needed deploy criterion.

## urlencoding 2.1.3 — support full proposal with codec limitations

ID `registry+https://github.com/rust-lang/crates.io-index#urlencoding@2.1.3`; archive SHA-256 `daf8dba3b7eb870caf1ddeed7bc9d2a049f3cfdfae7cb521b087cc33ae4c49da`. Read full `src/lib.rs`, `src/enc.rs`, `src/dec.rs`, `benches/bench.rs`, and both manifests; no build script or dependencies. `encode_into` copies only ASCII alphanumerics or `-._~`, and makes `%` plus two upper hex digits for every other byte; `from_utf8_unchecked` receives only those ASCII slices (enc.rs 78–130). `decode_binary` parses valid `%xx`, preserves incomplete/malformed percent text and literal `+`, and `decode` checks UTF-8 before returning owned strings (dec.rs 19–81). `NeverRealloc` would silently skip overflowing writes, but its buffer is reserved to the entire input size and every decode step emits at most the consumed byte count; this is a static bound argument, not a formal proof. It does not parse URLs, implement form-style `+` decoding, reject malformed percent text, prevent path traversal, normalize case or define authorization policy. The caller must choose correct parsing/decoding context and account for input size. No crate-local process/network/FFI or autonomous filesystem action was found.

Rust 1.94 compiled the exact source directly with `rustc --test --edition=2021`; 9/9 crate unit tests passed on aarch64-apple-darwin. Five lifetime-syntax warnings were emitted. The crate's nightly benchmark was read but not run. Support full `safe-to-deploy`, hence `safe-to-run`, for this byte codec with those explicit limits; tests do not establish correctness for all possible input bytes or application-specific decoding layers.
