## Scalar safety and iteration

The only unsafe operations are ten `char::from_u32_unchecked` calls: five in `lib.rs` at 134, 150, 189, 206, 222 and the five matching paths in `report.rs` at 96, 112, 145, 162, 178. I checked the actual branches and their duplicated error-reporting counterparts:

- Two-byte fast and fallback paths require lead `C2..DF` and continuation `80..BF`, yielding U+0080..U+07FF. Three-byte fallback and table-based fast paths require `E0 A0..BF`, `E1..EC 80..BF`, `ED 80..9F`, or `EE..EF 80..BF`, with the last byte `80..BF`; they exclude overlong values and surrogate code points.
- Four-byte fast paths accept `F0 90..BF`, `F1..F3 80..BF`, or `F4 80..8F`, with both trailing bytes in `80..BF`; the result is U+10000..U+10FFFF. The fallback never constructs a four-byte scalar: it consumes a valid three-byte prefix as an error when the fourth byte is unavailable or invalid. All indexed accesses are guarded by the input length; table indices are bounded by 383 in a 384-byte table.
- Reverse iteration visits at most four bytes, forms a suffix only at a non-continuation byte, and accepts it only when a forward decode consumes the entire suffix; otherwise it discards exactly one trailing byte as a replacement/error. `attempt` cannot exceed the number of bytes already visited, so the split/subslice arithmetic stays in bounds. Both iterators preserve valid U+FFFD separately from error reporting, and all yielding paths consume at least one input byte. `Utf8CharIndices` advances the front offset by bytes consumed from the front and computes a reverse result from front offset plus remaining length; `count`, `last`, and fused exhaustion were examined.

**Non-security API documentation discrepancy:** `indices.rs:97-98` says that `offset()` is the underlying string's length when there are no more characters. After constructing `Utf8CharIndices::new(b"a")` and consuming the only item via `next_back()`, `front_offset` has not been incremented, so `offset()` returns 0 even though the original length is 1. This is a documented-behavior mismatch, not a shown memory safety issue; consumers interpreting that sentence after reverse exhaustion could obtain the wrong position. It does not change this package-local safe-to-deploy judgment, and the bounded tests do not exclude all downstream misuse.
